## Implementation

### Mouse Button 상태 추가

- 기존 Keyboard `KeyState`와 같은 방식으로 Mouse Button의 Down·Up·Hold 상태를 관리하는 `MouseButtonState`를 추가했습니다.
- 왼쪽·오른쪽·가운데 버튼을 각각 Index `0`, `1`, `2`로 관리합니다.
- `GetMouseButtonDown()`, `GetMouseButtonUp()`, `GetMouseButton()`으로 Frame 단위 상태를 조회합니다.

```text
Mouse Button Index
0 → Left
1 → Right
2 → Middle

MouseButtonState
├─ isButtonDown : 이번 Frame에 처음 눌림
├─ isButtonUp   : 이번 Frame에 처음 해제됨
└─ isButton     : 현재 계속 눌린 상태
```

### Win32 Mouse Message 연결

- `WM_LBUTTONDOWN/UP`, `WM_RBUTTONDOWN/UP`, `WM_MBUTTONDOWN/UP`을 Input 상태로 변환합니다.
- Button Down 시 `SetCapture()`를 호출해 Pointer가 Window 밖으로 나가도 Mouse Message를 계속 받을 수 있도록 했습니다.
- Button Up 시 `ReleaseCapture()`를 호출합니다.

### Mouse 위치와 Frame 이동량

- `WM_MOUSEMOVE`의 `lParam`에서 X·Y 좌표를 읽어 현재 Mouse 위치로 저장합니다.
- `GET_X_LPARAM`, `GET_Y_LPARAM`을 사용해 음수 좌표가 가능한 Multi-monitor 환경을 고려했습니다.
- 현재 위치와 이전 Frame 위치의 차이로 `Mouse Delta X/Y`를 계산합니다.
- Frame 종료 시 현재 위치를 이전 위치로 복사해 다음 Frame의 Delta 기준으로 사용합니다.

```text
이번 Frame Mouse Position - 이전 Frame Mouse Position
= Mouse Delta
```

## Learned

### Mouse 위치와 Mouse Delta는 목적이 다르다

- Mouse Position은 Window Client 영역 안의 절대 좌표입니다.
- Mouse Delta는 이전 Frame에 비해 Pointer가 얼마나 이동했는지를 나타냅니다.
- UI Hit Test에는 Position이, Camera 회전처럼 이동 방향과 양이 필요한 처리에는 Delta가 주로 사용됩니다.

### Mouse Capture

- 일반적인 Mouse Message는 Pointer가 Window 밖으로 이동하면 해당 Window에 더 이상 전달되지 않을 수 있습니다.
- Button을 누를 때 Capture를 설정하면 Drag 도중 Pointer가 Window 밖으로 나가도 입력을 계속 받을 수 있습니다.
- Capture 해제 시점은 여러 Button의 동시 입력과 Drag 정책을 고려해야 합니다.

### `inline`의 두 가지 의미를 구분해야 한다

- C++의 `inline` 키워드는 같은 함수 정의가 여러 Translation Unit에 나타나는 것을 허용하는 ODR 관련 의미를 가집니다.
- Header에 함수 정의를 둘 때 각 `.cpp`에서 같은 정의를 보게 되므로 `inline`이 중복 정의 Link 오류를 방지합니다.
- 클래스 정의 내부에 작성한 Member Function은 `inline`을 직접 적지 않아도 암시적으로 inline입니다.
- `inline`은 Compiler가 Call을 반드시 함수 본문으로 치환한다는 보장이 아닙니다. Compiler는 `inline` 함수의 실제 치환을 거부할 수도 있고, 키워드가 없는 함수도 최적화 과정에서 치환할 수 있습니다.

```text
inline 키워드
→ Header의 동일 정의를 여러 Translation Unit에서 허용

실제 Inline Expansion 최적화
→ 함수 Call 대신 본문을 Call Site에 펼칠지 Compiler가 결정
```

### Inline 함수가 많을 때 가능한 문제

- `inline` 키워드만 많다고 실행 파일이 반드시 커지는 것은 아닙니다.
- 다만 Compiler가 많은 함수를 실제로 펼치면 같은 본문이 여러 Call Site에 복제되어 Code Size가 증가하고 Instruction Cache 효율이 떨어질 수 있습니다.
- Header에 구현이 많아지면 Header를 Include하는 Translation Unit이 모두 해당 구현을 Parsing·Compile하므로 Build 시간이 증가할 수 있습니다.
- Header 구현을 변경하면 이를 Include하는 여러 `.cpp`가 다시 Compile되어 변경 영향 범위가 커집니다.
- Macro나 Compile Option에 따라 Translation Unit마다 inline 함수 정의가 달라지면 ODR 위반이 발생할 수 있습니다.
- 최적화된 Build에서는 함수 Call 경계가 사라져 Debugging·Stack Trace·Profiling이 어려워질 수 있습니다.

### 오늘 코드의 inline 함수

- `Input.h`의 `GetMousePosition()`, `GetMouseDeltaX()`, `GetMouseDeltaY()`는 클래스 내부에 정의되어 있으므로 이미 암시적으로 inline입니다.
- 앞에 적힌 `inline`은 의도를 드러낼 수 있지만 중복 정의 허용을 위해 반드시 필요한 표기는 아닙니다.
- 이처럼 짧고 단순한 Getter는 Header에 두기 적합하지만, 크고 자주 변경되는 구현까지 모두 Header에 둘 필요는 없습니다.

## Problem / Solved

### Keyboard만 지원하는 Input 계층

**Problem**

- 기존 Input은 Keyboard의 Down·Up·Hold만 관리하며 Mouse Button과 이동량을 Gameplay에서 조회할 수 없었습니다.

**Solved**

- Mouse Button 상태와 Position·Previous Position을 추가하고 Win32 Mouse Message를 Frame 기반 Input 상태로 변환했습니다.

## Decision

- Mouse Button은 세 개를 지원하고 `0=Left`, `1=Right`, `2=Middle` Index를 사용합니다.
- Mouse Button의 Down·Up은 Frame 종료 시 초기화하고 Hold는 Button Up까지 유지합니다.
- Mouse Delta는 현재 위치에서 이전 Frame 위치를 빼서 계산합니다.
- Drag 중 Window 외부 입력을 받기 위해 Button Down 시 Mouse Capture를 설정합니다.

## Issue

- `WM_MOUSEMOVE` 처리 뒤 `return` 또는 `break`가 없어 현재 코드 흐름상 바로 다음 `WM_KILLFOCUS` 처리로 이어질 수 있습니다.
- `TestActor.cpp`에서 오른쪽 Button Down 확인 코드가 두 번 반복되고, 오른쪽 Button Up·Hold 확인은 없습니다.
- Button을 여러 개 동시에 누른 경우 한 Button Up에서 `ReleaseCapture()`가 호출되는 정책을 확인할 필요가 있습니다.
- Mouse Position은 Window Client 좌표이며 화면 좌표나 정규화 좌표로 변환하는 기능은 없습니다.
- 사용자 요청에 따라 위 항목은 수정하지 않았으며 빌드·실행·테스트도 수행하지 않았습니다.
