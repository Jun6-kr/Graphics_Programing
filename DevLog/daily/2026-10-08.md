## Learned

### Shared Ownership과 Weak Ownership

Level은 Actor를 `shared_ptr`로 소유하고 Actor는 Level을 `weak_ptr`로 참조한다. Actor와 Component도 같은 구조를 사용해 소유자는 객체 수명을 유지하면서 역방향 참조로 인한 순환 소유를 피한다.

### Container 변경의 지연 처리

Actor나 Component를 순회하는 도중 같은 Container에 요소를 직접 추가·삭제하면 Iterator가 무효화될 수 있다. 이번 구조에서는 별도의 추가 요청 목록과 삭제 Flag를 사용하고, Frame 처리 후 실제 Container 변경을 수행한다.

### Gameplay Event 전파

Engine이 Level을 호출하고, Level이 Actor를 호출하며, Actor가 Component에 Event를 전달한다. 각 객체는 활성화 및 BeginPlay 처리 여부를 확인해 필요한 대상만 실행한다.

## Problem / Solved

### Actor·Component 순회 중 Container 변경 위험

**Problem**

Gameplay Event 처리 중 Actor나 Component를 즉시 추가·제거하면 현재 순회 중인 `std::vector`의 Iterator와 참조가 무효화될 수 있다.

**Solved**

추가 요청은 별도 목록에 저장하고 삭제는 만료 Flag로 표시한 뒤, Frame 종료 시점의 처리 함수에서 실제 목록을 변경하도록 구성했다.

### Owner와 Child 사이의 순환 소유 가능성

**Problem**

Level과 Actor, Actor와 Component가 서로 `shared_ptr`로 참조하면 참조 횟수가 0이 되지 않는 순환 소유가 발생할 수 있다.

**Solved**

Level과 Actor가 Child를 `shared_ptr`로 소유하고, Actor와 Component의 Owner 참조는 `weak_ptr`로 저장했다.

### Actor Transform과 Render 제출 연결 부재

**Problem**

이전 Render Command 구조에는 World Matrix 제출 API가 있었지만, Gameplay Object에서 이를 호출하는 흐름이 없었다.

**Solved**

기본 `TransformComponent::Draw()`가 Transform을 갱신하고 World Matrix를 Renderer에 제출하도록 연결했다.

## Decision

- Level의 Actor 소유: `std::shared_ptr<Actor>`
- Actor의 Level 참조: `std::weak_ptr<Level>`
- Actor의 Component 소유: `std::shared_ptr<Component>`
- Component의 Actor 참조: `std::weak_ptr<Actor>`
- Actor·Component 추가 방식: 요청 목록에 저장 후 Frame 종료 시 반영
- Actor·Component 삭제 방식: 만료 Flag 설정 후 Frame 종료 시 제거
- 모든 Actor의 기본 공간 정보: `TransformComponent`
- Render 제출 위치: `TransformComponent::Draw()`
- Engine 종료 방식: `isQuit` Flag

## Issue

- `Engine::AddNewLevel<T>()`은 `std::shared_ptr<T>()`로 빈 Pointer를 만들고 `nextLevel`에 대입하며, 반환형이 있음에도 값을 반환하지 않는다. Template이 아직 사용되지 않아 현재 Build에서는 검출되지 않았다.
- `Level::FindActor<T>()`의 반복 변수 형식이 `std::shared_ptr<T>`이므로 `actorList`의 `std::shared_ptr<Actor>`에서 파생형 Pointer로 직접 변환할 수 없다. Template Instantiation 시 Compile 오류 가능성이 있다.
- `mainLevel`을 실제로 생성하고 설정하는 정상 경로가 아직 완성되지 않아 현재 상태에서는 Level Gameplay Event가 실행되지 않는다.
- Level 교체 시 기존 Level이나 Actor에 별도의 종료 Event를 전달하는 흐름은 없다.
- `Renderer::renderCommandList`를 Draw 완료 후 비우는 코드가 없어 매 Frame 제출된 Command가 누적될 수 있다.
- `Engine::Draw()`의 Clear Color 값 `200.0f`, `100.0f`, `150.0f`는 일반적인 정규화 범위 `0.0f`부터 `1.0f`를 벗어난다.
- `Sleep(1)` 기반 대기 구간이 계속 비활성화되어 Frame 제한 중 Busy-wait가 CPU를 점유한다.
