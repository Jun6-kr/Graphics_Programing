## Implementation

### Depth Stencil Texture와 View 생성

- 화면 크기와 같은 `ID3D11Texture2D` Depth Stencil Buffer를 추가했습니다.
- `D3D11_TEXTURE2D_DESC`에 Width·Height, Mip Level, Array Size, Format, Sample, Usage와 Bind 용도를 설정했습니다.
- Format은 24비트 Depth와 8비트 Stencil을 함께 저장하는 `DXGI_FORMAT_D24_UNORM_S8_UINT`를 사용합니다.
- 생성한 Texture로 `ID3D11DepthStencilView`를 만들어 Output Merger가 깊이 데이터를 기록할 수 있게 했습니다.

```text
D3D11_TEXTURE2D_DESC
→ ID3D11Texture2D DepthStencilBuffer
→ ID3D11DepthStencilView
→ Output Merger에 바인딩
```

### Depth Buffer 렌더링 연결

- Renderer 생성 시 Render Target과 같은 크기의 Depth Stencil을 생성합니다.
- `BeginScene()`에서 Render Target View와 Depth Stencil View를 함께 Output Merger에 바인딩합니다.
- Frame 시작 시 Color Buffer와 함께 Depth를 `1.0`, Stencil을 `0`으로 초기화합니다.
- Viewport의 Depth 범위를 Direct3D NDC Z 범위에 맞게 `0.0 ~ 1.0`으로 수정했습니다.

```text
Frame 시작
→ Color Target Clear
→ Depth 1.0 / Stencil 0 Clear
→ Draw
→ Fragment Depth 비교
→ 더 가까운 Fragment만 Color·Depth 갱신
```

### Resize와 Resource 수명 처리

- 화면 크기가 바뀌면 Context에서 기존 Render Target과 Depth Stencil의 바인딩을 해제합니다.
- 기존 DSV, Depth Texture, RTV를 해제한 뒤 새 화면 크기로 다시 생성합니다.
- 최소화처럼 Width 또는 Height가 0인 Resize는 Resource 생성을 건너뜁니다.
- Renderer 소멸 시 Depth Stencil View와 Texture를 해제합니다.

## Learned

### Depth는 2차원 화면에 저장하는 가시성 데이터

- 모니터에는 실제 깊이축이 없지만, 3차원 장면에서 어느 Fragment가 보이는지 결정하려면 Pixel별 깊이를 별도로 기억해야 합니다.
- Depth Buffer는 Color Buffer와 같은 Width·Height를 가진 2차원 Texture입니다.
- 일반적인 Direct3D Projection에서는 Near가 `0`, Far가 `1`에 가까우므로 작은 Depth가 더 가깝습니다.
- 기본 `LESS` 비교에서는 새 Depth가 기존 값보다 작을 때만 통과하고, 통과한 Fragment의 Color와 Depth가 갱신됩니다.

### 정렬과 Depth Buffer는 대체 관계가 아님

- 뒤에서 앞으로 정렬하면 나중에 그린 가까운 물체가 앞을 덮는 효과를 낼 수 있습니다.
- 그러나 교차하는 Geometry나 순환 가림 관계는 물체 단위 정렬만으로 정확히 해결할 수 없습니다.
- 실제 Renderer는 불투명 물체의 정확성과 성능을 위해 Depth Test와 앞에서 뒤 정렬을 함께 사용할 수 있습니다.
- 투명 물체는 Blend 때문에 뒤에서 앞으로 정렬하는 별도의 정책이 필요합니다.

### Color Buffer와 G-Buffer 구분

- 현재 Back Buffer의 Render Target은 최종 색상을 기록하는 Color Buffer입니다.
- G-Buffer는 Deferred Geometry Pass가 Albedo, Normal, Material, Depth 등 조명에 필요한 정보를 여러 Render Target에 저장한 묶음입니다.
- 따라서 모든 Color Buffer를 G-Buffer라고 부르는 것은 정확하지 않습니다.

### Forward와 Deferred Rendering

- Forward Renderer는 물체를 그릴 때 Lighting을 계산해 최종 Color Target에 직접 기록하는 방식입니다.
- Deferred Renderer는 Geometry 정보를 G-Buffer에 먼저 기록하고, 후속 Lighting Pass에서 그 데이터를 읽어 최종 화면을 만듭니다.
- Deferred를 단순히 “Draw Call을 여러 번 실행해 마지막에 합치는 방식”이라고만 정의하기보다 Geometry와 Lighting 단계의 분리로 이해해야 합니다.

### Texture2D Descriptor와 Mip Level

- `D3D11_TEXTURE2D_DESC`는 Texture 데이터가 아니라 GPU Texture Resource의 구조와 사용 목적을 설명합니다.
- Mip Level은 같은 이미지를 단계적으로 축소한 해상도 묶음입니다.
- 화면 해상도에 맞춰 매 Frame 깊이를 기록하는 현재 Depth Buffer에는 축소 Level이 필요하지 않아 `MipLevels = 1`을 사용합니다.

## Problem / Solved

### Depth Texture만 생성하고 사용하지 않는 상태

**Problem**

- Depth Texture 생성 코드만으로는 GPU가 렌더링 중 해당 Resource를 Depth Target으로 사용할 수 없습니다.
- DSV 생성, Output Merger 바인딩, Frame별 Clear와 Resource 해제가 연결되지 않은 상태였습니다.

**Solved**

- Texture로 DSV를 생성하고 RTV와 함께 Output Merger에 바인딩했습니다.
- Frame마다 Depth·Stencil을 초기화하고 Resize·소멸 시 Resource를 올바른 순서로 해제·재생성하도록 연결했습니다.

### Viewport Depth 범위가 `0 ~ 0`

**Problem**

- `viewport.MinDepth`와 `MaxDepth`가 모두 `0.0f`여서 모든 NDC Depth가 같은 값으로 매핑되는 설정이었습니다.

**Solved**

- Direct3D의 일반적인 NDC Z 범위에 맞게 `MinDepth = 0.0f`, `MaxDepth = 1.0f`로 수정했습니다.

## Decision

- Depth와 Stencil을 하나의 `DXGI_FORMAT_D24_UNORM_S8_UINT` Texture에 저장합니다.
- Depth Stencil의 화면 크기와 Sample 설정을 Render Target과 맞춥니다.
- 현재 Depth Texture는 Mip Chain 없이 한 Level만 생성합니다.
- 별도 Depth Stencil State를 생성하지 않고 Direct3D 11의 기본 Depth State를 사용합니다.

## Issue

- 현재 Stencil 저장 공간은 생성하지만 Stencil Test를 사용하는 기능은 없습니다.
- 불투명·투명 Render Queue 분리와 정렬 정책은 구현하지 않았습니다.
- G-Buffer와 Deferred Lighting Pass는 학습 메모일 뿐 현재 Renderer에는 구현되지 않았습니다.
- 실행 Smoke Test는 초기화 실패 여부만 확인했으며 화면 Pixel 결과를 자동 비교하지는 않았습니다.
