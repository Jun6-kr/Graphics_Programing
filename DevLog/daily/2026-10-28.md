## Implementation

### Vertex 구조체와 UV 속성

- Mesh 정점의 Position과 UV를 함께 보관하는 `Vertex` 구조체를 추가했습니다.
- `StaticMesh`의 정점 입력을 `std::vector<Vector3>`에서 `std::vector<Vertex>`로 변경했습니다.
- Triangle과 Quad의 각 Vertex에 `0 ~ 1` 범위의 UV 좌표를 지정했습니다.

```text
Vertex
├─ position : Vector3
└─ uv       : Vector2
```

### Input Layout 확장

- Vertex Buffer의 Position 다음에 UV가 저장되는 구조에 맞춰 Input Layout에 `TEXCOORD`를 추가했습니다.
- Position은 `DXGI_FORMAT_R32G32B32_FLOAT`, Byte Offset `0`을 사용합니다.
- UV는 `DXGI_FORMAT_R32G32_FLOAT`, Byte Offset `12`를 사용합니다.

```text
Vertex Buffer 한 정점
Byte 0  ~ 11 : Position float3
Byte 12 ~ 19 : UV float2
```

### Vertex Shader 입력 구조

- Default·Yellow Vertex Shader에 Position과 UV를 받는 `VSInput` 구조체를 추가했습니다.
- World·View·Projection 변환은 `input.position`을 사용하도록 변경했습니다.
- UV는 현재 Vertex Shader 입력까지만 추가됐으며 Pixel Shader 출력 경로에는 아직 전달되지 않습니다.

### GPU Texture Resource 생성

- `stbi_load()` 결과에서 Image Width와 Height를 Texture 멤버에 저장합니다.
- RGBA Pixel 배열과 `D3D11_SUBRESOURCE_DATA`를 사용해 `ID3D11Texture2D` 생성을 시도합니다.
- 한 행의 Byte 크기는 RGBA 4바이트를 반영해 `width × 4`를 `SysMemPitch`로 지정했습니다.
- GPU Resource 생성 요청 후 CPU Pixel 데이터는 `stbi_image_free()`로 해제합니다.

### Shader Resource View와 Sampler State

- Texture를 Shader Resource로 읽기 위한 `ID3D11ShaderResourceView` 멤버와 생성 코드를 추가했습니다.
- Min·Mag·Mip Linear Filter와 Wrap Address Mode를 사용하는 `ID3D11SamplerState`를 추가했습니다.
- `Texture::Bind(slot)`은 같은 Slot의 Pixel Shader Resource와 Sampler에 SRV·Sampler State를 각각 바인딩합니다.

```text
CPU RGBA Pixels
→ ID3D11Texture2D
→ ID3D11ShaderResourceView
→ PSSetShaderResources(slot)

Sampling 설정
→ ID3D11SamplerState
→ PSSetSamplers(slot)
```

## Learned

### Mapping은 서로 다른 데이터 영역의 대응

- Mapping은 한 영역의 값을 다른 영역의 값과 연결하는 것을 뜻합니다.
- Texture Mapping에서는 3차원 Mesh의 Vertex와 2차원 Texture 위치를 UV로 대응시킵니다.
- UV는 Texture Color 자체가 아니라 Texture에서 값을 읽을 위치를 나타냅니다.

### Vertex는 Position 이외의 속성도 가진다

- 모델의 Vertex에는 Position뿐 아니라 UV, Normal, Tangent, Vertex Color 등이 함께 저장될 수 있습니다.
- 현재 구현은 Position과 UV 두 속성을 하나의 Vertex Buffer에 교차 배치한 형태입니다.
- Input Layout은 각 속성의 Semantic, Format과 Byte Offset을 통해 Buffer의 어떤 값을 Shader 입력에 연결할지 설명합니다.

### UV에서 Color까지의 후속 흐름

```text
Vertex UV
→ Vertex Shader 입력
→ Rasterizer가 삼각형 내부에 보간
→ Pixel Shader 입력
→ Texture.Sample(Sampler, UV)
→ 최종 Color
```

- 현재 Commit은 이 흐름 중 Vertex UV, Input Layout, Texture Resource·SRV·Sampler 생성까지 작성했습니다.
- UV를 Pixel Shader로 전달하고 Sampling한 Color를 출력하는 단계는 아직 연결되지 않았습니다.

## Problem / Solved

### Position만 갖는 Vertex Buffer

**Problem**

- 기존 Vertex Buffer에는 Position만 있어 Texture의 어느 위치를 Mesh에 대응시킬지 전달할 속성이 없었습니다.

**Solved**

- `Vertex` 구조체에 Position과 UV를 함께 저장하고 Input Layout에 `TEXCOORD`를 추가했습니다.

### CPU Image Data 이후의 GPU Resource 경로

**Problem**

- 이전 구현은 `stbi_load()`로 CPU Pixel을 읽은 뒤 GPU Texture를 생성하지 않는 단계에서 끝났습니다.

**Solved**

- Texture2D, Shader Resource View와 Sampler State 생성 및 Pixel Shader Slot 바인딩 함수를 작성했습니다.

## Decision

- Vertex Position과 UV를 하나의 Vertex Buffer에 Interleaved 형태로 저장합니다.
- UV는 `Vector2`와 HLSL `float2`, Input Layout `R32G32_FLOAT`로 표현합니다.
- Image Texture Format은 `DXGI_FORMAT_R8G8B8A8_UNORM`을 사용합니다.
- Texture와 Sampler는 동일한 번호의 Pixel Shader Slot에 바인딩합니다.

## Issue

- HLSL `VSInput.position` Semantic이 `POSITIONT`로 작성돼 C++ Input Layout의 `POSITION`과 일치하지 않습니다.
- Vertex Shader가 UV를 Pixel Shader로 전달하지 않습니다.
- Pixel Shader에 `Texture2D`, `SamplerState`, UV 입력과 Sampling 코드가 없습니다.
- Test Level에서 `Texture::Bind()`를 호출하지 않습니다.
- Test Level의 지역 Texture는 `Initialized()` 종료 시 소멸하므로 지속적으로 소유되지 않습니다.
- Texture와 SRV의 Mip 설정이 `MipLevels = 0`, `MostDetailedMip = 1`로 작성돼 있으며 의도한 Mip 범위인지 확인이 필요합니다.
- `StaticMesh.cpp`, `Texture.cpp`에 후행 공백이 확인됐지만 소스는 수정하지 않았습니다.
- 사용자 요청에 따라 빌드·실행·테스트는 수행하지 않았습니다.
