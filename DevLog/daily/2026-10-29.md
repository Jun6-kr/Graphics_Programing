## Implementation

### Texture를 Render Command에 포함

- `StaticMeshComponent`가 `Texture`를 보관하고 Renderer에 Mesh·Shader·Texture·World Matrix를 함께 제출하도록 변경했습니다.
- `RenderCommand`에 Texture를 추가하고 Draw 전에 Texture의 SRV와 Sampler를 Pixel Shader의 0번 Slot에 바인딩합니다.
- Texture가 없는 Render Command는 기존처럼 Texture 바인딩 없이 처리합니다.

```text
StaticMeshComponent
→ Renderer::Submit(Mesh, Shader, Texture, World)
→ RenderCommand
→ Shader::Bind()
→ Texture::Bind(0)
→ DrawIndexed()
```

### UV를 Vertex Shader에서 Pixel Shader까지 전달

- C++ Input Layout과 HLSL 입력의 Position Semantic을 `POSITION`으로 일치시켰습니다.
- Yellow Vertex Shader의 출력 구조체에 `SV_POSITION`과 `TEXCOORD`를 선언했습니다.
- Vertex별 UV를 Vertex Shader Output으로 전달하면 Rasterizer가 삼각형 내부의 UV를 보간합니다.
- Yellow Pixel Shader는 보간된 UV를 사용해 `Texture2D.Sample()`을 호출하고 Sampling 결과를 최종 Color로 출력합니다.

### Texture Resource 설정 보완

- Texture2D와 Shader Resource View의 Mip Level을 한 Level로 설정했습니다.
- 가장 상세한 원본 Mip을 사용하도록 `MostDetailedMip`을 0으로 설정했습니다.
- Test Level에서 Texture를 불러와 두 Static Mesh Component에 지정했습니다.
- 실행 출력 폴더로 Assets를 복사하도록 프로젝트의 Pre-Build 명령을 변경했습니다.

## Learned

### Shader Semantic은 Stage 사이에서 값의 의미를 연결한다

- Semantic은 Shader 입력·출력 값이 무엇을 의미하는지 Pipeline에 알려주는 이름입니다.
- Vertex Shader가 Rasterizer에 전달할 위치에는 `SV_POSITION` System-value Semantic이 필요합니다.
- `SV_POSITION`이 구조체의 첫 번째 멤버여야 하는 것은 아닙니다. 선언 순서보다 Semantic 지정이 중요합니다.

### Vertex Shader 위치 출력이 float4인 이유

- Vertex Shader의 위치 출력은 Projection까지 적용된 Clip Space의 동차좌표 `(x, y, z, w)`입니다.
- `w`는 Clipping과 Perspective Divide에 사용되며, GPU는 이후 `(x/w, y/w, z/w)`를 계산해 NDC로 변환합니다.
- 따라서 `float4`가 필요한 핵심 이유는 이동·회전·스케일만이 아니라, Projection 이후의 동차좌표와 원근 나눗셈에 필요한 `w`까지 전달하기 위해서입니다.

```text
Local Position
→ World · View · Projection
→ Clip Space (x, y, z, w)
→ Clipping
→ Perspective Divide
→ NDC (x/w, y/w, z/w)
```

### Rasterizer는 Vertex 정보를 Pixel 후보로 변환한다

```text
Input Assembler
→ Vertex Shader
→ [Geometry Shader: 선택 단계]
→ Rasterizer
→ Pixel Shader
→ Output Merger
```

- Input Assembler는 Vertex·Index Buffer와 Input Layout을 이용해 Primitive를 구성합니다.
- Vertex Shader는 Vertex 단위로 위치와 속성을 처리합니다.
- Geometry Shader는 선택 단계이며 Primitive를 입력받아 새 Primitive를 생성하거나 변경할 수 있습니다.
- Rasterizer는 Vector 형태의 Primitive를 화면의 Pixel 후보인 Fragment로 변환하고 UV 같은 Vertex 속성을 보간합니다.
- Pixel Shader는 보간된 입력을 사용해 Color를 계산합니다.
- Output Merger는 Depth·Stencil Test와 Blending을 적용해 Render Target에 기록합니다.

### Sampler와 Material의 관계

- Texture는 Image Data이고, Shader Resource View는 Shader가 Texture를 읽는 관점입니다.
- Sampler State는 Texture 좌표 사이의 값을 어떻게 Filtering할지, 범위를 벗어난 UV를 Wrap·Clamp 등 어떤 방식으로 처리할지 정합니다.
- Unreal Engine의 Texture Sample Node는 Texture와 Sampling 동작을 함께 표현하지만, D3D11의 Sampler는 Texture 자체가 아니라 읽기 규칙입니다.
- 개념적으로 Material은 Shader만을 뜻하지 않습니다. Shader Program과 Texture·상수 같은 Parameter, Sampler, Blend·Depth·Rasterizer State 등을 묶어 하나의 표면 표현 방식을 구성합니다.

### Shader Compile Entry Point와 Target

- `fxc.exe`는 한 번의 Compile 명령에서 하나의 Entry Point와 하나의 Shader Target Profile을 지정해 하나의 Shader Binary를 만듭니다.
- 하나의 HLSL 파일에 Vertex Shader와 Pixel Shader Entry Point를 함께 작성할 수 있지만 각각 별도로 Compile해야 합니다.
- Batch File을 사용하면 같은 HLSL 파일을 대상으로 Entry Point와 Target을 바꾼 여러 Compile 명령을 순서대로 실행할 수 있습니다.

## Problem / Solved

### UV가 Pixel Shader까지 전달되지 않음

**Problem**

- Vertex Buffer와 Vertex Shader 입력에는 UV가 있었지만 Pixel Shader까지 이어지는 출력 경로가 없었습니다.

**Solved**

- Vertex Shader Output에 `TEXCOORD`를 추가하고 Pixel Shader 입력으로 연결해 Rasterizer가 보간한 UV로 Texture를 Sampling하도록 구현했습니다.

### Texture Resource가 Draw Command에 포함되지 않음

**Problem**

- 생성한 Texture를 객체별 Render Command가 소유하거나 Draw 전에 바인딩하는 경로가 없었습니다.

**Solved**

- Static Mesh Component에서 Texture를 지정하고 Render Command를 통해 전달하여 Draw 전에 바인딩하도록 연결했습니다.

## Decision

- Texture와 Sampler는 Pixel Shader의 같은 번호 Slot인 `t0`, `s0`에 바인딩합니다.
- 현재 Texture는 한 개의 Mip Level만 사용합니다.
- Texture가 없는 Render Command를 허용하기 위해 Texture 바인딩 전에 Null 여부를 확인합니다.

## Issue

- `DefaultVS.hlsl`은 UV를 입력받지만 Pixel Shader로 전달하는 출력 구조체는 아직 사용하지 않습니다.
- Texture를 지정하지 않은 Draw 다음에 이전 SRV가 Slot에 남을 수 있으므로, Null Texture Command에서 명시적으로 Unbind해야 하는지 후속 확인이 필요합니다.
- 프로젝트 Pre-Build 명령이 기존 HLSL 복사를 Assets 복사로 대체했으므로 Shader Binary 배치 흐름과 함께 확인이 필요합니다.
- 사용자 요청에 따라 빌드·실행·테스트는 수행하지 않았습니다.
