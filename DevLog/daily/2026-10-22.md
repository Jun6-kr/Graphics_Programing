## Implementation

### CameraComponent 추가

- Camera의 View·Projection 데이터를 생성해 Renderer에 제출하는 `CameraComponent`를 추가했습니다.
- 소유 Actor의 Position과 Rotation으로 `Matrix4::InverseTranslationRotation()`을 호출해 View Matrix를 만듭니다.
- Engine의 Client Width·Height와 Camera의 FOV·Near·Far를 사용해 Perspective Projection Matrix를 만듭니다.
- Test Level에 Z `-3` 위치의 Camera Actor를 생성해 새 경로가 실제로 실행되도록 연결했습니다.

```text
Camera Actor Transform
→ CameraComponent::Draw()
→ View / Projection 생성
→ Renderer::SubmitCamera()
→ CameraBufferData
→ Vertex Shader b1
```

### Camera 역변환 함수

- `Matrix4::InverseTranslationRotation()`을 추가했습니다.
- 현재 행벡터 규약에서 Camera의 순방향 변환 `R × T`를 View 변환으로 되돌리기 위해 `T⁻¹ × R⁻¹`을 반환합니다.
- `T⁻¹`은 Position의 부호를 반대로 하고, `R⁻¹`은 정규 직교 회전 행렬의 전치로 구합니다.

```text
Camera World Transform: R × T
View Matrix:           (R × T)⁻¹
                     = T⁻¹ × R⁻¹
```

### Perspective Projection Matrix

- 세로 FOV, 화면 Width·Height, Near·Far로 Direct3D 왼손 좌표계용 Perspective Matrix를 생성합니다.
- `S_y = 1 / tan(FOV_y / 2)`, `S_x = S_y / aspect`로 X/Y Scale을 구성합니다.
- Near와 Far를 Direct3D NDC Z 범위 `0 ~ 1`로 보내는 계수를 구성합니다.
- Clip Space의 `w`에 View Space의 `z`가 들어가도록 `m23 = 1`, `m33 = 0`으로 설정했습니다.

### WVP Shader 연결

- Camera Buffer에 View Matrix와 Projection Matrix를 함께 저장합니다.
- Vertex Shader가 Local Position에 World, View, Projection을 차례로 적용해 Clip Position을 반환하도록 변경했습니다.

```text
Local Position
→ × World      : 물체별 World 배치
→ × View       : Camera 기준 좌표
→ × Projection : Clip Space
→ GPU w Divide : NDC
```

- World Matrix는 물체마다 달라 `TransformBuffer : register(b0)`로 전달합니다.
- View·Projection은 같은 Camera로 그리는 물체들이 공유해 `CameraBuffer : register(b1)`로 전달합니다.

### Camera Constant Buffer 크기 수정

- `CameraBufferData`가 View와 Projection 두 행렬로 확장됐지만 Buffer 생성 크기가 한 행렬 크기로 남아 있던 오류를 수정했습니다.

```text
기존 GPU Buffer 크기: sizeof(Matrix4)          = 64 bytes
실제 복사 크기:       sizeof(CameraBufferData) = 128 bytes

수정 GPU Buffer 크기: sizeof(CameraBufferData) = 128 bytes
```

- D3D11 Constant Buffer의 `ByteWidth`는 16바이트 배수여야 하며, 현재 128바이트는 이 조건을 만족합니다.

## Learned

### WVP는 좌표가 지나가는 변환 단계

- World는 Local 정점을 공통 World에 배치합니다.
- View는 World의 점을 Camera 위치와 방향을 기준으로 다시 표현합니다.
- Projection은 Camera 공간의 Frustum을 Clip Space로 변환하고 Perspective Divide를 준비합니다.
- 세 행렬을 하나의 WVP로 미리 결합할 수도 있지만, 현재 구현은 물체별 World와 Camera 공통 View·Projection의 갱신 단위가 달라 Buffer를 분리합니다.

### Camera View는 Camera Transform의 역변환

- Camera를 오른쪽으로 움직이면 화면 속 World는 왼쪽으로 움직여 보입니다.
- 따라서 View Matrix에는 Camera Transform 자체가 아니라 반대 변환이 필요합니다.
- 행렬 곱의 역변환은 각 역행렬을 구하는 것뿐 아니라 순서도 반대로 뒤집어야 합니다.

### 16바이트 정렬은 Constant Buffer의 규칙

- 이번 메모의 “Buffer는 16byte로 정렬”은 D3D11 Constant Buffer의 `ByteWidth`와 HLSL Packing을 가리킵니다.
- Vertex Buffer와 Index Buffer까지 모두 동일한 16바이트 크기 규칙을 적용한다는 의미는 아닙니다.
- Matrix만 있을 때는 자연스럽게 16바이트 배수가 되지만, Scalar와 Vector가 섞이면 C++ 구조체와 HLSL Layout을 함께 확인해야 합니다.

### UI 메모

- `UI - context / immediate 방식`이라는 메모를 남겼습니다.
- 오늘 Commit에는 UI 구현이 없어 `context`가 가리키는 대상과 Immediate Mode UI의 구체적인 수업 내용을 확정할 근거가 없습니다.
- 후속 설명을 받은 뒤 개념과 구현 연결을 보완합니다.

## Problem / Solved

### Camera Buffer 할당 크기 불일치

**Problem**

- Camera 데이터가 View 한 행렬에서 View·Projection 두 행렬로 늘었지만 GPU Buffer는 64바이트로 생성되고 있었습니다.
- `UpdateCameraBuffer()`는 128바이트를 복사하므로 할당 범위를 넘어 쓸 수 있는 상태였습니다.

**Solved**

- `CreateCameraBuffer()`의 `ByteWidth`를 `sizeof(CameraBufferData)`로 변경해 생성 크기와 복사 크기, HLSL 선언을 128바이트로 일치시켰습니다.

### Level이 직접 Camera 행렬을 제출하던 구조

**Problem**

- 기존에는 Test Level의 `Draw()`가 직접 Eye·Target으로 View Matrix를 만들고 Renderer에 제출했습니다.

**Solved**

- Camera Actor의 Transform과 `CameraComponent`가 View·Projection을 구성하고 제출하도록 책임을 옮겼습니다.

## Decision

- 현재 Camera는 Scale을 제외하고 Position과 Rotation만 View 역변환에 사용합니다.
- World는 물체별 `b0`, View·Projection은 Camera 공통 `b1` Constant Buffer로 분리합니다.
- `SubmitCamera()`는 CPU 측 데이터를 제출하고 실제 GPU Camera Buffer 갱신은 `DrawScene()`에서 수행합니다.
- Camera Projection은 세로 FOV와 현재 Client Aspect Ratio를 사용합니다.

## Issue

- Camera가 움직이지 않을 때 Camera Buffer 갱신을 생략하는 Dirty Flag는 아직 구현하지 않았습니다.
- 여러 Camera가 제출되면 현재 구조에서는 마지막으로 제출된 Camera 데이터가 사용됩니다.
- `Renderer::CreateViewport()`의 `MaxDepth`가 현재 `0.0f`이므로 Depth Buffer 도입 전 `1.0f` 설정 여부를 확인해야 합니다.
- `UI - context / immediate 방식` 메모는 관련 코드와 설명이 없어 후속 확인이 필요합니다.
