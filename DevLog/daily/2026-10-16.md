### LookAt 뷰 행렬 추가

- `Matrix4::LookAt(eye, target, upVector)`를 추가했습니다.
- 카메라 위치와 바라보는 위치로부터 카메라의 정규 직교 기저를 계산합니다.

```text
Forward = normalize(Target - Eye)
Right   = normalize(Up × Forward)
Up      = normalize(Forward × Right)
```

- `Eye == Target`이면 시야 방향을 만들 수 없으므로 assert로 검사합니다.
- 입력 Up과 Forward가 평행하면 Right를 만들 수 없으므로 assert로 검사합니다.
- 카메라 위치를 각 카메라 축에 투영한 음수 값을 View 행렬의 이동 성분으로 사용합니다.

```text
x = -dot(Eye, Right)
y = -dot(Eye, Up)
z = -dot(Eye, Forward)
```

- 현재 프로젝트의 행벡터 규약에 맞게 Right, Up, Forward를 행렬의 열 방향으로 배치하고 이동 성분을 마지막 행에 저장합니다.

## Learned

### 그래픽스 파이프라인은 정보가 변환되는 연속 과정

Direct3D 11의 전체 그래픽스 파이프라인은 다음 순서로 구성됩니다.

```text
Input Assembler
→ Vertex Shader
→ Hull Shader
→ Tessellator
→ Domain Shader
→ Geometry Shader
→ Stream Output
→ Rasterizer
→ Pixel Shader
→ Output Merger
```

현재 CraftEngine은 Tessellation, Geometry Shader, Stream Output을 사용하지 않으므로 실제 학습 흐름은 다음과 같습니다.

```text
Input Assembler
→ Vertex Shader
→ Rasterizer
→ Pixel Shader
→ Output Merger
→ Render Target / Back Buffer
```

각 단계의 핵심은 앞 단계가 만든 정보를 다음 단계가 다른 의미의 정보로 변환한다는 것입니다.

| 단계 | 입력 정보 | 생성·변형되는 정보 |
|---|---|---|
| Input Assembler | Vertex Buffer, Index Buffer, Input Layout, Topology | Shader에 전달할 정점과 삼각형 구성 |
| Vertex Shader | 한 정점의 속성, 변환 행렬 | 변환된 정점 위치와 다음 단계에 전달할 속성 |
| Rasterizer | 변환된 삼각형 | 삼각형이 덮는 픽셀 후보와 보간된 값 |
| Pixel Shader | 보간된 정점 속성, Texture, Parameter | 픽셀별 출력 색상 |
| Output Merger | Pixel Shader 색상, Depth/Stencil, 기존 Render Target | 깊이 판정과 Blending을 거친 최종 픽셀 |

Microsoft 문서에서도 IA는 Vertex/Index Buffer로 Geometry를 공급하고, Vertex Shader는 정점별 변환을 수행하며, Rasterizer는 Vector 형태의 Primitive를 Pixel 형태로 바꾸고, Output Merger가 최종 색상·Depth·Stencil을 결합하는 단계로 설명합니다.

### Input Assembler 단계

Input Assembler는 아직 점을 이동시키거나 색을 계산하지 않습니다. 저장된 데이터를 해석해 어떤 정점들이 어떤 Primitive를 구성하는지 결정합니다.

```text
Vertex Buffer
→ 정점 번호별 위치와 속성

Index Buffer
→ Vertex Buffer에서 정점을 읽을 순서

Input Layout
→ 정점 한 개의 메모리를 POSITION, NORMAL, UV 등으로 해석하는 규칙

Primitive Topology
→ 읽은 정점을 점, 선, 삼각형 중 무엇으로 조립할지 결정
```

예를 들어 사각형의 Index Buffer가 `{ 0, 1, 2, 0, 2, 3 }`이면 IA는 첫 세 인덱스와 다음 세 인덱스로 삼각형 두 개를 구성합니다.

### 정점이 통과하는 좌표 공간

Vertex Shader에서 점 하나는 일반적으로 다음 공간을 순서대로 통과합니다.

```text
Local Space
→ World Matrix
→ World Space
→ View Matrix
→ View/Camera Space
→ Projection Matrix
→ Clip Space
→ Perspective Divide
→ NDC
→ Viewport Transform
→ Screen Space
```

- Local Space: Mesh 자체를 기준으로 저장된 원본 정점 위치
- World Space: 장면 전체를 기준으로 한 위치
- View Space: 카메라를 원점으로 다시 표현한 위치
- Clip Space: Projection까지 적용되고 화면 절두체 판정에 사용할 위치
- NDC: `x/w`, `y/w`, `z/w`로 나눈 정규화 좌표
- Screen Space: Viewport 크기에 맞춘 실제 화면 위치

현재 `DefaultVS.hlsl`은 World Matrix만 적용한 값을 바로 `SV_POSITION`으로 반환합니다.

```hlsl
float4 worldPosition = mul(float4(pos, 1), world);
return worldPosition;
```

아직 View와 Projection이 없으므로 완성된 3D 카메라 파이프라인은 아닙니다. 현재 도형이 보이는 이유는 World 좌표가 우연히 Clip/NDC 범위와 비슷한 작은 값 안에 있기 때문입니다.

### 동차좌표를 사용하는 이유

3차원 위치 `(x, y, z)`에 `w`를 추가해 `(x, y, z, w)`로 표현합니다.

```text
w = 1 → 위치(Point)
w = 0 → 방향(Direction)
```

이 구분 때문에 동일한 4×4 행렬을 사용해도 Translation은 위치에만 적용되고 방향에는 적용되지 않습니다.

```text
Point     (x, y, z, 1) × Translation → 이동됨
Direction (x, y, z, 0) × Translation → 이동되지 않음
```

동차좌표가 제공하는 중요한 의미는 다음과 같습니다.

1. 이동·회전·크기 변환을 모두 하나의 4×4 행렬 곱으로 표현할 수 있습니다.
2. 여러 변환을 하나의 행렬로 합칠 수 있습니다.
3. Projection 이후 `w`로 나누는 원근 투영을 표현할 수 있습니다.

즉 차원을 하나 늘리는 것은 계산을 복잡하게 만들기 위한 것이 아니라, Translation과 Perspective를 행렬 연산 체계 안에 포함시키기 위한 방법입니다.

### World Matrix의 S × R × T 순서

현재 프로젝트는 정점을 행벡터로 취급합니다.

```cpp
worldMatrix = Scale * Rotation * Translation;
```

따라서 정점은 식의 왼쪽에서 오른쪽 순서로 변환됩니다.

```text
p_world = p_local × S × R × T

1. Local 원점을 기준으로 크기 변경
2. Local 원점을 기준으로 회전
3. World 위치로 이동
```

이 순서가 중요한 이유는 행렬 곱셈이 교환법칙을 만족하지 않기 때문입니다.

```text
S × R != R × S
R × T != T × R
```

예를 들어 Translation을 먼저 적용한 뒤 Rotation하면 물체 자체뿐 아니라 이동 벡터까지 회전해 물체가 원점을 중심으로 공전하게 됩니다. Translation을 먼저 적용한 뒤 Scale하면 위치 값까지 확대되어 원점에서의 거리도 바뀝니다.

```text
S → R → T
물체 자체를 크기·회전시킨 뒤 원하는 World 위치에 배치

T → R
먼저 이동한 위치까지 원점 기준으로 회전
→ 물체가 원점 주위를 도는 결과
```

열벡터 convention을 사용하는 교재에서는 같은 적용 순서를 `T × R × S × p`처럼 반대로 표기합니다. 공식을 외우기 전에 이 프로젝트가 `p × Matrix`인 행벡터 convention이라는 점을 먼저 확인해야 합니다.

### 외적 순서와 부호

외적은 두 벡터 모두에 수직인 벡터를 만들지만 순서를 바꾸면 방향이 반대가 됩니다.

```text
A × B = -(B × A)
```

현재 왼손 View 구성에서는 `+Z`를 Forward로 사용하고 다음 순서로 카메라 기저를 만듭니다.

```text
Right = Up × Forward
Up    = Forward × Right
```

예를 들어 기본 Up `(0, 1, 0)`과 Forward `(0, 0, 1)`을 사용하면 다음 결과가 나옵니다.

```text
Up × Forward = (1, 0, 0) = Right
Forward × Up = (-1, 0, 0) = Left
```

따라서 `Cross()` 호출 순서는 단순한 문법 차이가 아니라 카메라의 Right/Left 방향과 삼각형 Winding 방향을 바꿀 수 있는 의미 있는 선택입니다.

좌표계가 왼손인지 오른손인지와 Cross 함수 자체의 항 순서를 섞어서 외우기보다, 먼저 Forward 축을 무엇으로 정의했는지 확인하고 실제 기준 벡터를 대입해 원하는 Right가 나오는지 검증하는 편이 안전합니다.

### View 변환은 카메라 World Transform의 역변환

카메라도 World 안에 위치와 회전을 가진 객체입니다. 하지만 장면을 그릴 때는 카메라를 움직이는 대신, World의 모든 점을 카메라와 반대 방향으로 옮기고 회전시켜 카메라가 원점에 있는 것처럼 만듭니다.

```text
카메라가 오른쪽으로 +5 이동
→ World의 모든 점을 왼쪽으로 -5 이동

카메라가 오른쪽으로 회전
→ World의 모든 점을 반대 방향으로 회전
```

이를 수식으로 표현하면 다음과 같습니다.

```text
View Matrix = inverse(Camera World Matrix)
```

행벡터 convention에서 Scale이 없는 카메라 World Matrix를 다음처럼 두면:

```text
Camera World = Rotation × Translation
```

곱의 역행렬은 순서가 뒤집히므로:

```text
View
= inverse(Rotation × Translation)
= inverse(Translation) × inverse(Rotation)
= T⁻¹ × R⁻¹
```

- `T⁻¹`: 카메라 위치의 반대 방향으로 World 이동
- `R⁻¹`: 카메라 회전의 반대 방향으로 World 회전

Translation 행렬 하나의 역은 위치에 `-1`을 곱해 만들 수 있습니다. 다만 Rotation과 결합된 행렬 전체를 역변환할 때는 반드시 곱셈 순서까지 뒤집어야 합니다.

### 정규 직교 행렬에서 전치 행렬이 역행렬인 이유

정규 직교 기저는 다음 두 조건을 만족합니다.

```text
각 축의 길이 = 1
서로 다른 축의 내적 = 0
```

회전 행렬의 축이 정규 직교하면 행렬의 행 또는 열은 서로 독립된 단위 축입니다. 전치하면 이 축을 행과 열 사이에서 교환할 수 있고 다음 관계가 성립합니다.

```text
RᵀR = I
따라서 R⁻¹ = Rᵀ
```

이 성질은 순수 회전 행렬에 적용됩니다. 비균등 Scale이나 Shear가 섞이면 축 길이와 직교성이 깨질 수 있으므로 단순 전치를 역행렬로 사용할 수 없습니다.

### LookAt 방식으로 View 행렬 만들기

View 행렬을 만드는 첫 번째 방법은 Camera Transform의 역행렬을 직접 구하는 것입니다. 두 번째 방법인 `LookAt()`은 카메라가 바라볼 Target과 기준 Up을 이용해 Camera 축을 바로 구성합니다.

```text
Forward = normalize(Target - Eye)
Right   = normalize(Up × Forward)
Up      = normalize(Forward × Right)
```

그 다음 World의 점 `P`를 카메라 기준으로 표현합니다.

```text
P_view.x = dot(P - Eye, Right)
P_view.y = dot(P - Eye, Up)
P_view.z = dot(P - Eye, Forward)
```

분배하면 다음처럼 됩니다.

```text
dot(P - Eye, Right)
= dot(P, Right) - dot(Eye, Right)
```

그래서 코드의 마지막 이동 성분이 단순히 `-Eye.x`, `-Eye.y`, `-Eye.z`가 아니라 다음 값입니다.

```cpp
float x = -eye.Dot(right);
float y = -eye.Dot(up);
float z = -eye.Dot(forward);
```

이는 카메라 위치를 World 축이 아니라 새로 만든 Camera Right/Up/Forward 축을 기준으로 역이동시키기 때문입니다.

## Problem / Solved

### 카메라 기준 좌표계를 만드는 방법

- 카메라 위치와 Target만으로는 Forward만 얻을 수 있어 Roll 방향을 결정할 수 없습니다.
- 기준 Up을 추가하고 외적을 사용해 Right와 보정된 Up을 만들어 정규 직교 카메라 기저를 구성했습니다.

### View 이동 성분 계산

- View 행렬의 이동을 단순히 `-Eye`로 넣지 않고 카메라 기저 각각에 대한 음의 내적으로 계산했습니다.
- 이 방식으로 World 위치를 카메라 Right/Up/Forward 축 좌표로 투영합니다.

## Decision

- CraftEngine은 기존 코드에 맞춰 행벡터와 `p × Matrix` 규약을 유지합니다.
- World Matrix의 적용 순서는 `Scale × Rotation × Translation`을 사용합니다.
- 왼손 View에서 Forward는 `Target - Eye`로 계산합니다.
- Right는 `Up × Forward`, 보정된 Up은 `Forward × Right`로 계산합니다.
- 정규 직교 Rotation의 역행렬은 Transpose로 계산합니다.

## Issue

- `LookAt()`은 구현됐지만 아직 Camera 객체나 Renderer에 연결되지 않았습니다.
- Vertex Shader의 Constant Buffer에는 World Matrix만 있고 View·Projection Matrix가 없습니다.
- Vertex Shader가 World 위치를 바로 `SV_POSITION`으로 반환하므로 완성된 Clip Space 변환이 아닙니다.
- Perspective Projection Matrix가 구현되지 않았습니다.
- LookAt 결과를 알려진 카메라 위치와 축으로 검증하는 단위 테스트가 없습니다.
- Camera Up과 Forward가 거의 평행할 때 assert 외의 Runtime 복구 방식이 없습니다.

## Next

- Perspective Projection Matrix를 구현합니다.
- Constant Buffer에 World, View, Projection 정보를 전달합니다.
