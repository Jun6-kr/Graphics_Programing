## Implementation

### HLSL Build-time Compile과 CSO 출력

- Visual Studio의 `FxCompile` 단계가 `DefaultVS.hlsl`, `DefaultPS.hlsl`을 빌드할 때 Compile하도록 구성했습니다.
- 생성된 Shader Bytecode를 실행 파일의 `HLSLShaders/` 디렉터리에 출력합니다.

```text
HLSLShaders/DefaultVS.hlsl
→ Build FxCompile
→ Bin/Debug/HLSLShaders/DefaultVS.cso

HLSLShaders/DefaultPS.hlsl
→ Build FxCompile
→ Bin/Debug/HLSLShaders/DefaultPS.cso
```

### Runtime Shader Compile에서 CSO Load로 변경

- `Shader`가 `.hlsl` Source를 Runtime에 Compile하던 경로 대신 `.cso` 파일을 읽도록 변경했습니다.
- `D3DReadFileToBlob()`으로 Bytecode를 읽고, 해당 Blob을 `CreateVertexShader()`, `CreatePixelShader()`, `CreateInputLayout()`에 전달합니다.
- CSO 읽기 실패 오류 메시지의 오탈자를 수정했습니다.

```text
기존
HLSL Source → D3DCompileFromFile → Shader Bytecode → D3D Shader

변경
Build 시 HLSL → CSO
Runtime에 CSO → D3DReadFileToBlob → D3D Shader
```

## Learned

### View Frustum

View Frustum은 Camera가 볼 수 있는 3차원 시야 영역입니다. Perspective Camera에서는 Camera에서 멀어질수록 넓어지는 절두체 형태입니다.

| 요소 | 의미 |
|---|---|
| FOV | Camera의 시야각 |
| Near Plane | 너무 가까운 Geometry를 잘라내는 평면 |
| Far Plane | 너무 먼 Geometry를 잘라내는 평면 |
| Aspect Ratio | 화면의 `width / height` 비율 |

Near Plane보다 가깝거나 Far Plane보다 먼 점, FOV 바깥의 점은 Clipping 대상이 됩니다.

### Vertical FOV와 정규화된 Focal Length

오늘 학습은 세로 FOV `θ`, 왼손 좌표계의 `+Z` Forward, 행벡터, 대칭 Frustum을 기준으로 합니다.

세로 반높이가 1인 정규화된 Projection Plane이 Camera에서 `d`만큼 떨어져 있다면 다음 직각삼각형 관계가 성립합니다.

```text
tan(θ/2) = 1/d

d = 1 / tan(θ/2)
```

여기서 `d`는 실제 Camera Lens의 물리적 mm 단위 초점거리라기보다, 정규화한 Projection Plane에서 사용하는 Focal Length Scale입니다.

- FOV가 작아지면 `tan(θ/2)`가 작아져 `d`가 커집니다.
- FOV가 커지면 `tan(θ/2)`가 커져 `d`가 작아집니다.

같은 물체와 Camera 거리 기준으로 화면에 보이는 크기는 다음과 같습니다.

- FOV가 작아지면 좁은 영역을 확대해서 보므로 물체가 크게 보입니다.
- FOV가 커지면 넓은 영역을 담으므로 같은 물체가 작게 보입니다.

따라서 “FOV가 커지면 상이 커진다”는 메모는 반대로 정정해야 합니다.

### 삼각형의 닮음을 이용한 Y Projection

View Space의 점을 다음처럼 둡니다.

```text
P_view = (x, y, z), z > 0
```

Camera 원점에서 점으로 향하는 선과 Projection Plane이 만나는 위치는 삼각형의 닮음으로 구할 수 있습니다.

```text
y_projected / d = y / z

y_projected = d × y / z
```

Projection Plane의 세로 반높이를 1로 정규화했으므로 이 값이 NDC Y 좌표에 대응합니다.

```text
S_y = d = 1 / tan(θ/2)

y_NDC = y × S_y / z
      = y / (z × tan(θ/2))
```

여기서 `z`로 나누는 것이 Perspective의 핵심입니다. 같은 `y`라도 `z`가 커지면 NDC에서의 크기가 작아집니다.

### X Projection과 Aspect Ratio

세로 반높이를 1로 두면 가로 반너비는 `aspect = width / height`입니다. 가로 좌표를 같은 NDC `-1 ~ 1` 범위에 맞추려면 Aspect Ratio로 한 번 더 나눕니다.

```text
S_x = S_y / aspect

x_NDC = x × S_x / z
      = x / (z × aspect × tan(θ/2))
```

화면이 가로로 넓어져 Aspect Ratio가 커지면 같은 View Space X 값이 NDC에서는 더 작게 변환됩니다. 이를 통해 가로로 넓은 화면에서도 물체 비율이 찌그러지지 않습니다.

### Perspective Projection의 X/Y 핵심 식

```text
S_y = 1 / tan(FOV_y / 2)
S_x = S_y / aspect

x_NDC = x × S_x / z
y_NDC = y × S_y / z
```

Projection Matrix는 Vertex Shader에서 직접 `x/z`, `y/z`를 계산하는 대신 다음 단계로 나눌 수 있게 구성합니다.

```text
Projection Matrix 적용
→ Clip Space (x_clip, y_clip, z_clip, w_clip)
→ w_clip에 View Space z가 들어감
→ GPU Perspective Divide
→ x_NDC = x_clip / w_clip
→ y_NDC = y_clip / w_clip
```

즉 Projection Matrix의 목적 중 하나는 나중에 GPU가 `w`로 나눴을 때 삼각형의 닮음에서 유도한 `x/z`, `y/z`가 나오도록 Clip 좌표를 구성하는 것입니다.

### Near/Far와 Z Projection은 아직 미완료

오늘 자료에서는 FOV와 Aspect Ratio로 X/Y Scale을 유도했습니다. Perspective Matrix를 완성하려면 View Space의 Near/Far 범위를 Direct3D NDC의 Z 범위 `0 ~ 1`로 옮기는 항도 유도해야 합니다.

```text
View Space
→ Projection Matrix
→ Clip Space
→ Clipping
→ Perspective Divide
→ NDC
→ Viewport Transform
→ Screen Space
```

현재 코드에는 Perspective Projection Matrix가 아직 구현되지 않았습니다.

### PCH가 해결하는 문제

각 `.cpp` 파일이 `<Windows.h>`, `<d3d11.h>`, 표준 Library Header처럼 거의 변하지 않는 큰 Header를 반복해서 Parse하면 Build 시간이 늘어납니다. PCH는 공통 Header의 Compile 결과를 재사용합니다.

- PCH Header가 자주 바뀌면 관련 파일을 대규모로 다시 Compile할 수 있습니다.
- 자주 변경되는 프로젝트 Header를 무분별하게 넣기보다 안정적이고 반복 사용되는 Header를 넣는 것이 적절합니다.
- PCH는 Runtime 성능 최적화가 아니라 Build 시간 최적화입니다.

### Build-time Shader Compile의 의미

HLSL 오류를 Application 실행 중이 아니라 Build 단계에서 발견할 수 있고, Runtime에는 이미 Compile된 Bytecode를 읽습니다.

다만 현재 FxCompile 로그의 Target은 기존 Runtime Compile의 `vs_5_0`, `ps_5_0`과 달리 `vs_4_0_level_9_3`, `ps_4_0_level_9_3`입니다. 의도한 Shader Model인지 확인하고 Project 설정에 명시할 필요가 있습니다.

## Problem / Solved

### Runtime HLSL Compile 의존

**Problem**

- 기존에는 Application 실행 시마다 `D3DCompileFromFile()`로 HLSL Source를 Compile했습니다.

**Solved**

- Build 단계에서 CSO를 생성하고 Runtime에는 `D3DReadFileToBlob()`으로 Bytecode를 읽도록 변경했습니다.

### 반복 Header Compile

**Problem**

- 여러 Source가 공통 표준 Library와 Windows·Direct3D Header를 반복해서 Compile했습니다.

**Solved**

- CraftEngine과 Game에 각각 PCH를 구성했습니다.

## Decision

- HLSL은 Build 단계에서 Compile하고 Runtime에는 CSO를 Load합니다.
- CSO 출력 위치는 실행 파일 기준 `HLSLShaders/`로 맞춥니다.
- CraftEngine과 Game은 서로 다른 PCH를 사용합니다.
- Perspective Projection은 세로 FOV, 왼손 좌표계, `+Z` Forward, 행벡터 규약을 기준으로 학습합니다.

## Issue

- Perspective Projection Matrix와 Z Depth 변환은 아직 코드에 구현되지 않았습니다.
- `Shader.cpp`에 이전 Runtime Compile 코드가 주석 상태로 남아 있습니다.
- FxCompile Target이 기존 Runtime Target `5_0`과 다른 `4_0_level_9_3`으로 확인됐습니다.
- CSO 출력 경로는 x64 설정에만 추가되어 Win32 구성에서는 Runtime 경로와 일치하지 않을 수 있습니다.
- 프로젝트의 `v145` Toolset과 현재 환경의 `v143` 사이에 차이가 있습니다.
