## Implementation

- `AssetManager::LoadMesh()`는 정점 수와 인덱스 수를 연속해서 읽은 뒤 각 배열을 복원합니다. 이 부분의 읽기 순서를 `.cmesh` Writer와 맞췄습니다.
- `StaticMesh::LoadFromFile()`은 `.cmesh`를 읽고, 애셋 정점에서 위치와 UV를 꺼내 엔진의 `Vertex`로 변환합니다. 변환된 정점과 인덱스로 기존 `StaticMesh` 생성 경로를 사용합니다.
- `Texture::LoadFromFile()`은 `.ctexture`를 읽고 4채널인지 검사한 뒤 `LoadFromPixels()`에 픽셀과 크기를 전달합니다. 이 함수가 D3D11 텍스처와 SRV를 생성합니다. RGBA8에서 픽셀 하나는 4바이트이므로 한 행의 바이트 수인 `SysMemPitch`는 `width * 4`입니다.
- `TestLevel`의 왼쪽 액터에 `Sphere.cmesh`로 만든 메시를 지정하고, 텍스처 머티리얼은 `T_Checker.ctexture`를 사용하도록 변경했습니다. 저장소의 `Sphere.cmesh`도 갱신했습니다.

## Learned

### 하나의 리소스에 여러 View 사용

- 텍스처 리소스는 데이터를 보관하고, View는 파이프라인에서 그 리소스를 어떤 용도와 포맷으로 사용할지 지정합니다. 같은 리소스에 View를 여러 개 생성해 데이터를 공유할 수 있습니다.
- 예를 들어 깊이 텍스처에 DSV(Depth-Stencil View)를 만들어 첫 번째 패스의 깊이 검사와 기록에 사용하고, SRV(Shader Resource View)를 만들어 후속 패스의 셰이더에서 깊이를 읽을 수 있습니다.
- 깊이 리소스를 두 용도로 쓰려면 생성 시 `D3D11_BIND_DEPTH_STENCIL | D3D11_BIND_SHADER_RESOURCE`를 지정하고, 두 View의 포맷이 호환되도록 리소스 포맷을 선택합니다. 일반적인 패스 전환에서는 쓰기 가능한 DSV를 해제한 뒤 같은 영역을 SRV에 바인딩합니다.
- 현재 CraftEngine에서 깊이 버퍼는 DSV 용도로 생성되고, `.ctexture`에서 만든 텍스처는 SRV 용도로 생성됩니다. 이 메모는 하나의 깊이 리소스를 두 패스에서 재사용하는 학습 예시입니다.
