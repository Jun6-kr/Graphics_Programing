## Learned

### Frame 단위 Render Command 수명

TransformComponent는 매 Frame 현재 World Matrix를 Renderer에 제출한다. 따라서 Render Command 목록도 한 Frame 동안만 유효해야 하며, Draw가 끝난 뒤 정리해야 이전 Transform이 반복해서 그려지지 않는다.

### Delta Time 기반 회전

Frame마다 고정 각도를 더하는 대신 초당 회전 속도에 `deltaTime`을 곱하면 Frame Rate가 달라져도 같은 시간 동안 비슷한 각도로 회전한다.

```text
이번 Frame의 회전량 = 초당 회전 속도 × deltaTime
```

### Game 진입점에서 초기 Level 구성

실행 Project가 Engine을 생성하고 초기 Level을 요청하면, Engine은 Main Loop의 안전한 전환 시점에 해당 Level을 활성화하고 초기화한다.

## Problem / Solved

### 회전 전 상태가 화면에 계속 남는 현상

**Problem**

매 Frame 새로운 World Matrix가 `renderCommandList`에 추가되지만 처리 후 목록을 비우지 않아 이전 회전 상태의 Command도 계속 다시 그려졌다. Back Buffer는 정상적으로 Clear되고 있었지만 같은 Frame에서 과거 Transform을 모두 다시 Draw해 잔상처럼 보였다.

**Solved**

현재 Frame의 Command 순회가 끝난 뒤 `renderCommandList.clear()`를 호출해 다음 Frame에는 새로 제출된 Transform만 처리하도록 수정했다.

### 초기 Level이 생성되지 않음

**Problem**

기존 `AddNewLevel<T>()`은 빈 `shared_ptr`을 `nextLevel`에 대입해 실제 Level 객체를 만들지 않았다.

**Solved**

`std::make_shared<T>()`로 Level을 생성하도록 수정하고, Application 시작 시 `TestLevel`을 등록했다.

### Test Source Build 경고

**Problem**

새 Test 파일의 Source Encoding과 `double` Literal 사용으로 C4819 및 C4305 경고가 발생했다.

**Solved**

필요한 파일에 UTF-8 BOM을 적용하고 Scale 값을 Float Literal로 변경했다.

## Decision

- 초기 Level 등록 위치: `LaunchApplication()`
- Level 생성 방식: `std::make_shared<T>()`
- Test Actor 회전축: Z축
- 회전량 계산: `speed * deltaTime`
- Render Command 수명: 한 Frame
- Command 정리 시점: `DrawScene()`의 Command 처리 직후
- Clear Color: 정규화된 Float 값
- Swap Effect: `DXGI_SWAP_EFFECT_DISCARD`

## Issue

- `DXGI_SWAP_EFFECT_DISCARD`로 변경한 이유와 `FLIP_DISCARD` 대비 동작·성능 차이는 코드에서 확인되지 않는다.
- `Level::FindActor<T>()`의 반복 변수 형식 문제는 아직 남아 있으며 Template Instantiation 시 Compile 오류 가능성이 있다.
- TestActor는 공용 Demo Vertex·Index Buffer를 사용하므로 Actor별 Mesh 정보는 아직 Render Command에 포함되지 않는다.
- `Sleep(1)` 기반 Frame 대기 구간이 비활성화되어 Busy-wait가 CPU를 계속 점유한다.
- Render Command에는 World Matrix만 있으며 View·Projection 변환은 아직 포함되지 않는다.
