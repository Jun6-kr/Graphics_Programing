## Implementation

- 파일 순회에서 `.fbx`를 판별해 `ImportMesh()`를 호출합니다. Assimp로 씬을 읽고 삼각형 변환, 스무스 노멀 생성, 탄젠트 공간 계산, 동일 정점 병합, 캐시 지역성 개선, 왼손 좌표계 변환 옵션을 적용합니다.
- 각 메시의 Position과 제공되는 UV·Normal·Tangent·Bitangent를 공용 정점 배열에 추가합니다. 삼각형 면의 인덱스에는 `vertexBase`를 더해 합쳐진 정점 배열을 참조하도록 합니다.
- 원본 메시마다 서브 메시 하나를 만들고, 공용 인덱스 배열에서 시작 위치와 개수를 기록합니다. 머티리얼의 첫 번째 외부 Diffuse Texture를 찾으면 `.ctexture`로 변환하고 출력 루트 기준 상대 경로를 기록합니다.
- `WriteMeshAsset()`에 서브 메시 개수와 각 항목을 쓰는 코드를 추가했습니다. 작업 파일에는 `Sphere.fbx`, `Sphere.cmesh`, `T_Checker.ctexture`가 포함되어 있습니다.
- Engine이 `AssetManager`를 생성합니다. `LoadMesh()`와 `LoadTexture()`는 기본적으로 `Assets/Imported`를 기준으로 파일을 찾고, 매직 바이트와 버전을 검사한 뒤 CPU 쪽 자료구조로 읽습니다. 동일한 이름으로 다시 요청하면 캐시된 객체를 반환합니다.
- `TestLevel` 초기화에 `Meshes/Sphere.cmesh` 로드 호출을 추가했습니다. 구체 메시를 GPU 버퍼와 렌더링에 연결하는 단계는 남아 있습니다.

## Learned

- `vertexBase`는 각 메시의 로컬 정점 번호를 공용 정점 배열의 번호로 바꿉니다. 예를 들어 앞 메시의 정점이 100개라면 다음 메시의 로컬 인덱스 2는 공용 배열의 102를 가리킵니다. `indexOffset`과 `indexCount`는 공용 인덱스 배열에서 해당 서브 메시의 범위를 지정합니다.
- 바이너리 파일의 형식은 필드의 타입과 순서까지 포함합니다. 매직과 버전이 일치해도 Writer와 Reader가 개수를 다른 위치에서 처리하면 이후 필드를 올바르게 읽을 수 없습니다.
- 가변 길이 경로 문자열은 객체의 메모리 표현 대신 바이트 수와 실제 문자 데이터를 저장해야 다른 프로세스에서 복원할 수 있습니다. 프로젝트의 `WriteString()`과 `ReadString()`이 이 방식을 사용합니다.
- 애셋 파일을 CPU 자료구조로 복원하고 캐싱하는 과정 이후에, 렌더링에 사용할 GPU 버퍼와 텍스처를 생성하는 단계가 이어집니다.

## Issue

- `.cmesh` Writer는 정점 수와 인덱스 수를 연속으로 쓴 뒤 정점 배열을 씁니다. Reader는 정점 수 다음에 정점 배열을 기대하고 그 뒤 인덱스 수를 읽습니다.
- 서브 메시 텍스처 경로는 Writer에서 `WritePod()`로 쓰지만 Reader는 길이와 문자 바이트를 읽는 `ReadString()`을 사용합니다. Writer와 Reader의 형식을 맞춘 뒤 기존 산출물의 재생성 여부를 확인해야 합니다.
