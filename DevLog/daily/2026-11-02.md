## Implementation

### Material 추상화 추가

- Shader와 Shader가 사용하는 Texture를 함께 관리하고 바인딩하기 위한 `Material` 기반 클래스를 추가했습니다.
- 모든 Material이 자체 리소스를 Pipeline에 설정할 수 있도록 `Bind()`를 순수 가상 함수로 선언했습니다.
- Texture를 사용하지 않는 `DefaultMaterial`과 Texture 한 장을 사용하는 `TextureMappingMaterial`을 구현했습니다.

```text
Material
├─ DefaultMaterial
│  └─ Default Shader
└─ TextureMappingMaterial
   ├─ TextureMapping Shader
   └─ Texture 1개
```

### Render Command를 Material 중심으로 변경

- `StaticMeshComponent`가 Shader와 Texture를 각각 보관하는 대신 Material을 보관하도록 변경했습니다.
- Renderer의 `Submit()`과 `RenderCommand`도 개별 Shader·Texture 대신 Material을 전달받습니다.
- Draw 시 Renderer는 Mesh를 바인딩한 뒤 Material의 `Bind()`를 호출합니다.
- Shader와 Texture의 구체적인 바인딩 방식은 Renderer가 아니라 각 Material 구현이 담당합니다.

```text
StaticMeshComponent
├─ StaticMesh
└─ Material
      ↓ Submit
RenderCommand
├─ Mesh
├─ Material
└─ World Matrix
      ↓ Draw
Mesh::Bind()
Material::Bind()
DrawIndexed()
```

### Test Level의 Material 적용

- Triangle에는 Texture를 사용하지 않는 `DefaultMaterial`을 지정했습니다.
- 두 Quad에는 같은 `TextureMappingMaterial`을 지정해 Shader와 Texture를 함께 공유하도록 구성했습니다.
- `Material.cpp`와 `Material.h`를 CraftEngine 프로젝트와 Filter에 추가했습니다.

## Learned

### Shader마다 요구하는 Resource 구성이 다르다

- 어떤 Shader는 Texture를 전혀 사용하지 않을 수 있습니다.
- 어떤 Shader는 Albedo·Normal·Roughness 등 여러 Texture와 Constant Buffer를 요구할 수 있습니다.
- Component나 Renderer가 모든 가능한 Resource를 개별 인자로 받기 시작하면 Shader 종류가 늘어날수록 인터페이스가 복잡해집니다.

```text
Texture 없는 Shader
→ Shader만 Bind

Texture 1개를 사용하는 Shader
→ Shader + Texture(t0) + Sampler(s0) Bind

Texture N개를 사용하는 Shader
→ Shader + Texture(t0...tn) + Sampler + Constant Buffer Bind
```

### Material은 Shader가 요구하는 Resource 묶음과 바인딩 규칙이다

- Material은 단순히 `Shader + Texture 1개`로 고정된 구조가 아닙니다.
- Material은 사용할 Shader, Shader Parameter, Texture·Constant Buffer 같은 Resource와 각 Slot에 바인딩하는 방식을 함께 표현할 수 있습니다.
- Renderer는 Material 내부의 구체적인 Texture 개수를 알 필요 없이 `Material::Bind()`만 호출할 수 있습니다.
- 현재 구현에서는 파생 Material 클래스가 각 Shader에 필요한 Resource 구성과 Binding 순서를 직접 정의합니다.

### 같은 Material을 여러 Object가 공유할 수 있다

- 같은 표면 표현을 사용하는 여러 Component는 하나의 Material 인스턴스를 공유할 수 있습니다.
- 현재 Test Level의 두 Quad는 같은 `TextureMappingMaterial`을 사용하므로 같은 Shader와 Texture를 공유하고 World Matrix만 다르게 제출합니다.
- Mesh는 형상, Material은 표면 표현, World Matrix는 객체별 배치를 담당합니다.

```text
Object A ─┐
          ├─ 같은 Mesh / Material 공유 가능
Object B ─┘

각 Object마다 다른 값
→ World Matrix
```

## Problem / Solved

### Renderer가 Shader와 Texture 구성에 직접 의존

**Problem**

- 기존 Render Command는 Shader와 Texture 한 개를 별도 멤버로 고정해 보관했습니다.
- Texture가 필요 없는 Shader와 여러 Texture가 필요한 Shader를 지원하려면 Renderer의 제출 인자와 바인딩 코드가 계속 달라질 수 있었습니다.

**Solved**

- Shader와 필요한 Resource를 Material 내부로 이동하고, Renderer는 Material의 공통 `Bind()` 인터페이스만 호출하도록 변경했습니다.

## Decision

- `Material`은 `Bind()`를 제공하는 추상 기반 클래스로 정의합니다.
- Shader별 Resource 구성은 `DefaultMaterial`, `TextureMappingMaterial` 같은 파생 클래스에서 관리합니다.
- Static Mesh Component와 Render Command는 개별 Shader·Texture 대신 Material을 참조합니다.
- 같은 Material 인스턴스를 여러 Component가 공유할 수 있습니다.

## Issue

- `TestLevel.cpp`에는 Material 적용 이전의 Shader·Texture 생성 코드와 주석 처리된 코드가 일부 남아 있습니다.
- 현재 Material은 Shader별 파생 클래스로 고정되어 있어 Shader 종류가 늘어나면 Material 클래스 수도 증가할 수 있습니다.
- Texture N개, Constant Buffer Parameter와 Render State를 일반적으로 등록·관리하는 구조는 아직 구현되지 않았습니다.
- Material을 캐시하거나 재사용하는 Material Manager는 아직 없습니다.
- 사용자 요청에 따라 빌드·실행·테스트는 수행하지 않았습니다.
