## Implementation

### 확장자 기반 Texture Import 연결

- Source Directory를 순회하며 각 파일의 확장자를 얻습니다.
- 확장자를 소문자로 변환해 대소문자가 다른 파일도 같은 종류로 판별합니다.
- TGA·TARGA·JPG·JPEG·PNG 파일을 Texture로 분류하는 `IsTexture()`를 추가했습니다.
- Texture 파일의 Source 상대 경로를 유지한 `.ctexture` 출력 경로를 만든 뒤 `ImportTexture()`를 호출합니다.
- 하나 이상의 Import가 실패하면 Process Exit Code `3`을 반환하도록 전체 성공 상태를 누적합니다.

```text
Source Directory 순회
→ Extension 소문자 변환
→ Texture 여부 판별
→ RelativeOutput(..., ".ctexture")
→ ImportTexture()
→ 전체 성공 여부 반환
```

### stb_image 구현부 위치 정리

- `STB_IMAGE_IMPLEMENTATION`과 `stb_image.h` Include를 `TextureImporter.h`에서 `TextureImporter.cpp`로 이동했습니다.
- Header에는 함수 선언과 필요한 기본 Type만 남겼습니다.
- stb_image 구현이 여러 Translation Unit에서 중복 생성될 위험을 줄였습니다.

### 가변 길이 문자열 Binary 기록

- `WriteString()`에서 먼저 문자열 Byte 수를 `uint32_t`로 기록합니다.
- 이어서 문자열의 실제 Character 배열을 지정된 크기만큼 기록합니다.

```text
String Binary Layout
├─ uint32_t length
└─ char[length] data
```

### Mesh Asset 자료구조 정의

- Importer와 Engine이 공유할 `AssetVector2`, `AssetVector3`, `AssetVertex`를 추가했습니다.
- Vertex에 Position·UV·Normal·Tangent·Bitangent 정보를 저장하도록 정의했습니다.
- Index 범위와 Texture Asset 경로를 보관하는 `AssetSubMesh`를 추가했습니다.
- Vertex·Index·SubMesh 배열을 묶는 `MeshAsset`을 정의했습니다.

```text
MeshAsset
├─ vertices
│  └─ position / uv / normal / tangent / bitangent
├─ indices
└─ subMeshes
   ├─ indexOffset
   ├─ indexCount
   └─ textureAsset
```

### Mesh Binary Writer 초기 구현

- Mesh 출력 Directory를 만들고 Binary Stream을 생성합니다.
- `MESH` Magic과 Asset Version을 기록합니다.
- Vertex·Index 개수와 각 배열의 Raw Data를 차례대로 기록합니다.
- Assimp의 Scene·Mesh·Material을 사용할 Mesh Import 함수와 Diffuse Texture Import 함수의 인터페이스를 추가했습니다.

## Learned

### 파일 종류 판별과 Import Dispatch

- Asset Importer의 Main은 원본 Format을 직접 변환하기보다 확장자로 파일 종류를 판별해 전용 Import 함수로 전달할 수 있습니다.
- 확장자를 소문자로 정규화하면 `.PNG`, `.Png`, `.png` 같은 표기 차이를 하나의 조건으로 처리할 수 있습니다.
- 여러 파일을 처리할 때 각 결과를 누적하면 전체 Batch 작업의 성공·실패를 Exit Code로 전달할 수 있습니다.

### Header와 Implementation 분리

- `STB_IMAGE_IMPLEMENTATION`은 stb_image 함수 본문을 실제로 생성하므로 하나의 Translation Unit에서만 정의해야 합니다.
- 구현 Macro를 Header에 두면 그 Header를 Include하는 여러 `.cpp`에서 같은 함수 본문이 생성될 수 있습니다.
- Header에는 Interface를 두고 구현 생성은 `.cpp` 하나에 한정하는 이유를 확인했습니다.

### Mesh를 Vertex와 Index만으로 끝내지 않는 이유

- Mesh Vertex에는 위치뿐 아니라 Texture Mapping과 Lighting에 필요한 UV·Normal·Tangent·Bitangent가 포함될 수 있습니다.
- 하나의 Model 안에서도 Material이나 Texture가 다른 여러 영역이 존재할 수 있으므로 SubMesh 단위의 Index 범위가 필요합니다.
- SubMesh는 전체 Vertex·Index Buffer를 공유하면서 서로 다른 Material 단위로 Draw Call을 나누는 기준이 될 수 있습니다.

### Binary String 직렬화

- Binary Stream에는 문자열 끝을 자동으로 알 수 있는 구조가 없으므로 길이와 데이터를 함께 저장해야 합니다.
- Reader는 먼저 길이를 읽고 그 크기만큼 Character Data를 읽어 문자열을 복원할 수 있습니다.

## Problem / Solved

### Texture Import 함수가 Main 흐름과 연결되지 않음

**Problem**

- Texture Import 함수와 출력 경로 계산 함수는 존재했지만 Source 파일 순회에서 호출되지 않았습니다.

**Solved**

- 확장자를 판별하고 Texture 파일마다 `.ctexture` 경로를 생성해 `ImportTexture()`를 호출하도록 연결했습니다.

### stb_image 구현 Macro가 Header에 위치

**Problem**

- `STB_IMAGE_IMPLEMENTATION`이 Header에 있어 여러 Translation Unit에서 중복 정의될 가능성이 있었습니다.

**Solved**

- 구현 Macro와 stb_image Include를 `TextureImporter.cpp`로 옮겨 하나의 Translation Unit에서만 구현되도록 구성했습니다.

## Decision

- Texture 확장자 판별 전에 문자열을 소문자로 변환합니다.
- TGA·TARGA·JPG·JPEG·PNG를 Texture Source Format으로 인식합니다.
- Import 중 하나라도 실패하면 Importer Process가 실패 Code `3`을 반환합니다.
- Mesh Vertex에는 Position·UV·Normal·Tangent·Bitangent를 저장합니다.
- SubMesh는 Index Offset·Count와 Texture Asset 경로를 보관합니다.

## Issue

- Main은 아직 Mesh 확장자를 판별하거나 `ImportMesh()`를 호출하지 않습니다.
- `ImportMesh()`와 `ImportDiffuseTexture()`는 현재 기본값만 반환하는 Stub입니다.
- `WriteMeshAsset()`은 SubMesh 배열을 아직 기록하지 않으며 성공 경로의 반환값도 없습니다.
- `TextureAsset`의 Height Member가 `hegiht`로 작성된 상태입니다.
- Binary 배열을 구조체 Memory 그대로 기록하므로 Padding·Format 호환성 정책을 이후 명확히 정할 필요가 있습니다.
- 사용자 요청에 따라 위 항목은 수정하지 않았으며 빌드·실행·테스트도 수행하지 않았습니다.
