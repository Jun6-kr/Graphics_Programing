## Implementation

### Craft 전용 Asset Type 정의

- Importer와 Engine이 함께 사용할 공용 Asset 정의를 `Includes/CraftAssets/AssetTypes.h`에 추가했습니다.
- Mesh와 Texture Binary를 구분하기 위한 Magic Signature를 정의했습니다.
- Asset Format 변경을 식별하기 위한 Version 값을 추가했습니다.
- Texture의 Width·Height·Channel 수와 Pixel 배열을 표현하는 `TextureAsset` 구조체를 추가했습니다.

```text
Texture Asset
├─ Magic     : CTEX
├─ Version   : 1
├─ Width
├─ Height
├─ Channels  : 4
└─ RGBA Pixel Bytes
```

### 원본 이미지를 RGBA Pixel로 변환

- `stbi_load()`로 JPG·PNG 등의 원본 이미지를 읽습니다.
- `STBI_rgb_alpha`를 지정해 원본 Channel 구성과 관계없이 RGBA 4채널 Pixel Data로 변환합니다.
- Asset 작성이 끝나면 `stbi_image_free()`로 CPU Pixel Memory를 해제합니다.

### Binary Texture Asset 작성

- 출력 Directory를 생성하고 `std::ofstream`의 Binary Mode로 `.ctexture` 파일을 작성합니다.
- Magic, Version, Width, Height, Channel 수, Pixel 배열 순서로 데이터를 기록합니다.
- 고정 크기 값은 `WritePod()`를 통해 Byte 그대로 기록합니다.

```text
JPG / PNG
→ stb_image Decode
→ RGBA Pixel Array
→ Craft Texture Header + Pixel Bytes
→ .ctexture
```

### Source 상대 경로를 유지한 출력 경로

- `std::filesystem::relative()`로 입력 Root를 제외한 상대 경로를 계산합니다.
- `replace_extension()`으로 Engine 전용 확장자를 적용합니다.
- Output Root와 결합해 Source Directory 구조를 유지한 출력 경로를 생성합니다.

```text
Assets/Source/Textures/T_Checker.png
→ Assets/Imported/Textures/T_Checker.ctexture
```

## Learned

### Engine 전용 Binary Asset Format

- Magic Signature는 파일이 기대한 Asset 종류인지 빠르게 확인하기 위한 식별 값입니다.
- Version은 저장 Format이 변경됐을 때 Reader가 호환 여부를 판단하는 기준입니다.
- Metadata 뒤에 Pixel Byte 배열을 연속 기록하면 Runtime에서 원본 이미지 Decode 없이 Texture 생성에 필요한 데이터를 읽을 수 있습니다.

### Binary Serialization

- `std::ofstream`에 `std::ios::binary`를 지정하면 Text 변환 없이 Byte 단위로 기록할 수 있습니다.
- `reinterpret_cast<const char*>`를 사용해 고정 크기 값의 Memory 표현을 Stream에 전달합니다.
- POD의 정확한 표현은 `Plain Old Data`이며, 현재 `WritePod()`는 고정 크기 일반 데이터를 기록하는 용도로 사용됩니다.

### 경로와 변환 로직의 분리

- `RelativeOutput()`은 입력 파일의 종류를 해석하지 않고 출력 경로 계산만 담당합니다.
- `ImportTexture()`는 이미지 Decode와 Asset 작성 흐름을 담당합니다.
- `WriteTextureAsset()`은 전달받은 Pixel과 Metadata를 Binary Format으로 기록하는 역할을 담당합니다.

## Problem / Solved

### 원본 Texture를 Runtime에서 직접 읽는 구조

**Problem**

- 원본 이미지 Format을 Engine 전용 형식으로 변환하고 저장할 함수가 없었습니다.

**Solved**

- 이미지를 RGBA Pixel로 Decode한 뒤 Magic·Version·Metadata·Pixel Data를 포함하는 `.ctexture` Binary를 작성하는 기능을 추가했습니다.

## Decision

- Texture Asset Magic은 `CTEX`, 현재 Asset Version은 `1`을 사용합니다.
- Imported Texture는 RGBA 4채널로 통일합니다.
- Source의 Directory 구조를 Imported Directory에도 유지합니다.
- 고정 크기 값과 Pixel 배열을 Binary Stream에 순서대로 기록합니다.

## Issue

- `Main.cpp`에서 파일 확장자를 구분해 `ImportTexture()`를 호출하는 흐름은 아직 연결되지 않았습니다.
- `WriteString()`은 선언되어 있지만 구현이 비어 있습니다.
- `TextureAsset`의 Height Member가 `hegiht`로 작성되어 있습니다.
- `STB_IMAGE_IMPLEMENTATION`이 Header에 정의되어 있어 해당 Header를 여러 Translation Unit에서 Include하면 중복 정의 위험이 있습니다.
- Engine에서 `.ctexture`를 읽는 Deserialization과 GPU Texture 생성 경로는 아직 없습니다.
- 사용자 요청에 따라 위 항목은 수정하지 않았으며 빌드·실행·테스트도 수행하지 않았습니다.
