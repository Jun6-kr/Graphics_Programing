## Learned

### Draw Command와 Draw Call

현재 코드에서 `RenderCommand`는 CPU가 그리기에 필요한 데이터를 모아 둔 구조체입니다.

```text
RenderCommand
├─ Mesh
├─ Shader
└─ World Matrix
```

Renderer가 명령 하나를 처리하면서 다음 코드를 호출하면 실제 Draw Call이 발생합니다.

```cpp
context->DrawIndexed(command.mesh->GetIndexCount(), 0, 0);
```

현재 구조에서는 유효한 Render Command 하나가 처리될 때 `DrawIndexed()`가 한 번 호출되므로, 결과적으로 Render Command 하나당 Draw Call 하나가 발생합니다. 다만 Draw Command는 엔진이 정의한 데이터 단위이고, Draw Call은 Direct3D API를 통해 GPU 작업을 요청하는 호출이라는 점에서 같은 개념은 아닙니다.

### Draw Call과 Pass는 다르다

Pass는 렌더링 목적과 출력 대상을 기준으로 나눈 **큰 렌더링 단계**입니다. 한 Pass 안에서 장면의 여러 객체를 그리기 위해 여러 Draw Call이 발생할 수 있습니다.

```text
Pass
├─ Render Target 및 Depth Target 선택
├─ 해당 단계의 Shader와 Render State 설정
└─ 여러 Draw Command 처리
   ├─ Draw Call
   ├─ Draw Call
   └─ Draw Call
```

따라서 다음 관계로 이해해야 합니다.

```text
Draw Call != Pass
하나의 Pass 안에 여러 Draw Call이 포함될 수 있음
```

### Pass 수와 이미지 수

`3 Pass이면 이미지 세 장, 4 Pass이면 이미지 네 장`이라고 항상 대응하지는 않습니다.

- 한 Pass가 하나의 Render Target에 결과를 기록할 수 있습니다.
- MRT(Multiple Render Targets)를 사용하면 한 Pass가 여러 이미지에 동시에 기록할 수 있습니다.
- 여러 Pass가 같은 이미지에 순서대로 기록할 수도 있습니다.
- Shadow Pass처럼 색상 이미지 대신 Depth Texture만 만드는 Pass도 있습니다.
- 중간 결과를 다음 Pass에서 사용하려면 별도의 Texture를 만들기도 합니다.

예를 들어 다음 구조는 세 단계의 Pass를 가집니다.

```text
1. Shadow Pass
   └─ 여러 물체를 Draw하여 Shadow Map 생성

2. Scene Pass
   └─ 여러 물체를 Draw하여 장면 색상 생성

3. Post-process Pass
   └─ 장면 색상을 입력받아 최종 Back Buffer에 출력
```

여기서 중요한 기준은 이미지 장수 자체가 아니라 **각 단계가 어떤 목적과 출력 대상을 가지고 장면을 그리는가**입니다. 현재 CraftEngine에는 별도의 Pass 추상화가 없으며, Back Buffer를 대상으로 장면을 그리는 단일 흐름만 존재합니다.

### 점의 이동은 Vertex Shader에서 계산

현재 Vertex Shader는 Vertex Buffer에서 받은 위치와 Transform Constant Buffer의 World Matrix를 곱합니다.

```hlsl
float4 worldPosition = mul(float4(pos, 1), world);
```

Vertex Buffer의 원본 점을 직접 변경하는 것이 아니라, Vertex Shader가 각 정점의 출력 위치를 계산합니다. World Matrix가 달라지면 같은 Mesh를 사용해도 위치, 회전, 크기가 다른 결과를 만들 수 있습니다.

### 객체별 Shader 선택

오늘 변경으로 Shader는 Renderer 전체에 고정되지 않고 Render Command마다 전달됩니다.

```text
Actor A → Mesh A + Shader A + World Matrix A
Actor B → Mesh B + Shader B + World Matrix B
```

Pixel Shader가 서로 다른 색상을 반환한다면 객체마다 다른 색상 결과를 만들 수 있습니다. 다만 현재 Test Level은 하나의 Shader를 세 Actor가 공유하므로, 객체별로 서로 다른 Shader를 사용하는 화면은 아직 구현되지 않았습니다.
