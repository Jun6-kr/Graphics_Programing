## Learned

### 정점 버퍼와 인덱스 버퍼는 Mesh의 핵심 데이터

오늘 메모의 구분을 현재 코드에 맞춰 정리하면 다음과 같습니다.

```text
Mesh
├─ Vertex Buffer: 정점의 위치와 정점 속성
├─ Index Buffer: 정점을 조합해 삼각형을 만드는 순서
└─ Submesh 범위, Primitive Topology 등의 그리기 정보
```

이번에 추가한 `StaticMesh`는 이 중 Vertex Buffer와 Index Buffer를 하나의 지오메트리 리소스로 묶은 첫 단계입니다. 현재 정점 형식은 위치를 나타내는 `Vector3`만 포함합니다.

### Shader와 Material의 관계

학습 단계에서 `셰이더 → 머티리얼`로 구분하면 렌더링 외형을 담당하는 영역을 Mesh와 분리해 이해하는 데 도움이 됩니다. 다만 실제 Material은 Shader 자체와 완전히 같은 개념이라기보다, 일반적으로 다음 데이터를 묶은 렌더링 설정입니다.

```text
Material
├─ 사용할 Shader
├─ Texture
├─ 색상·거칠기 등의 Parameter
└─ Sampler·Blend·Rasterizer 등의 Render State
```

즉 Mesh는 **무엇을 그릴지**, Material은 **어떻게 보이게 그릴지**를 담당합니다. 현재 코드에는 별도의 Material 클래스가 아직 없으며, Renderer가 공통 Vertex Shader와 Pixel Shader를 사용합니다.

### 한 모델과 여러 번의 Draw Call

메모의 `한 모델링 - 여러 개의 셰이더 - 여러 개의 ???`에서 `???`는 기본적인 렌더링 구조에서는 보통 **Draw Call**로 연결됩니다.

```text
하나의 Model Asset
→ 여러 Mesh 또는 Submesh
→ 여러 Material Slot
→ Material/Shader 그룹별 Draw Call
```

모델의 일부마다 다른 Material을 사용하면 해당 부분을 별도로 바인딩하고 그려야 하므로, 일반적으로 Material 또는 Submesh 단위로 Draw Call이 나뉩니다. 배칭, 인스턴싱 등의 최적화에 따라 실제 호출 수는 달라질 수 있습니다.

### FBX Import와 Runtime 데이터

FBX는 Maya나 Blender 같은 DCC(Digital Content Creation) 도구와 게임 엔진 사이에서 모델 데이터를 전달하기 위한 교환 형식입니다. FBX에는 다음과 같이 편집과 제작을 위한 다양한 데이터가 들어갈 수 있습니다.

- 정점, 인덱스, Normal, Tangent, UV
- Mesh와 Material Slot
- 계층 구조와 Transform
- Bone, Skinning, Animation
- Camera, Light, 사용자 속성 등의 부가 데이터

게임 엔진은 FBX 전체를 런타임에서 그대로 사용할 필요가 없습니다. Import 단계에서 필요한 데이터만 추출·검증·변환하고, 엔진 전용 Asset과 GPU용 Vertex/Index Buffer로 만드는 방식이 일반적입니다. 따라서 “언리얼에서는 필요하지 않은 데이터가 많다”는 메모는, 정확히는 **제작 도구용 데이터 중 게임 런타임에 불필요한 항목은 Import 과정에서 제외하거나 엔진 형식으로 변환한다**는 의미로 정리할 수 있습니다.

```text
FBX Model Asset
├─ Geometry / Material Slot
├─ Bone / Animation
├─ Hierarchy / Transform
└─ 제작 도구용 부가 데이터
          ↓ Import
필요한 데이터만 추출·변환
          ↓
Engine Asset → Mesh / Material / Animation → GPU Resource
```

## Problem / Solved

### Renderer가 임시 Mesh 데이터를 직접 소유하던 문제

- 기존에는 `Renderer`가 삼각형용 Vertex/Index Buffer를 직접 만들고 고정된 index 개수 `3`을 사용했습니다.
- Mesh 데이터를 `StaticMesh`로 분리하고 `RenderCommand`가 그릴 Mesh를 참조하도록 변경했습니다.
- 이제 `DrawIndexed()`는 명령에 포함된 Mesh의 index 개수를 사용합니다.

## Decision

- GPU 지오메트리 버퍼의 생성·바인딩·해제 책임을 `StaticMesh`에 모았습니다.
- `RenderCommand`는 Mesh와 World Matrix를 한 그리기 단위로 묶습니다.
- Renderer는 Render Command를 순회하며 Mesh를 바인딩한 뒤 그리는 역할을 담당합니다.
- 삼각형 생성은 범용 생성자와 분리된 정적 팩토리 함수로 제공했습니다.
