## Problem / Solved

### 0에 가까운 값으로의 벡터 나눗셈

**Problem**

벡터의 정규화나 나눗셈 연산에서 0 또는 0에 가까운 값을 나누면 유효하지 않은 결과가 발생할 수 있다.

**Solved**

- `Normalized()`에서 벡터 길이가 `KindaSmallNumber` 이하인지 검사
- 벡터·Scalar 나눗셈에서 각 나누는 값의 절대값을 검사
- 조건에 해당하면 `assert` 실패를 발생시키고 Zero 벡터 반환 또는 기존 값 유지

---

## Decision

코드에서 직접 확인되는 설정과 표현 방식은 다음과 같다.

- `Vector3`는 행벡터로 사용
- 기본 방향은 Right `(+X)`, Up `(+Y)`, Forward `(+Z)`로 정의
- 벡터 간 곱셈·나눗셈은 각 성분별 연산으로 구현
- 0 여부는 정확한 비교 대신 `KindaSmallNumber`를 기준으로 판단
- `Matrix4`의 기본 생성 결과는 단위 행렬
- 회전 역행렬은 기저 축이 서로 직교하는 행렬에 한해 전치 행렬로 계산

---

## Issue

- `Vector3::operator==()`는 부동소수점 성분을 정확히 비교하므로, 계산 결과 비교에 사용할 경우 오차 기준이 필요한지 확인해야 한다.
- `Matrix4::operator=`의 인자가 값으로 전달되어 대입 전에 복사 생성자가 한 번 추가로 호출된다.
- `InverseRotation()`은 직교 회전 행렬에서만 전치를 역행렬로 사용할 수 있으므로 Scale·Shear가 포함된 행렬에는 사용할 수 없다.
- `Matrix4` 멤버 주석에서 `m30`~`m33`이 3행으로 표기되어 있어 4행으로의 수정을 검토해야 한다.
- 추가된 벡터·행렬 연산에 대한 자동화 테스트는 이 commit에서 확인되지 않는다.
