## Learned

### 데이터와 View를 함께 준비하는 이유

- GPU Resource는 실제 데이터를 저장하고, View는 Pipeline이 그 데이터를 어떤 용도로 바라볼지를 정의합니다.
- Depth 구현에서는 `ID3D11Texture2D`에 깊이값을 저장하고 `ID3D11DepthStencilView`를 Output Merger에 바인딩합니다.
- 일반 Image Texture는 `ID3D11Texture2D`에 Pixel을 저장하고, Shader가 읽을 수 있도록 `ID3D11ShaderResourceView`를 만들어 Shader Stage에 바인딩해야 합니다.
- 따라서 “데이터와 View를 바인딩한다”는 표현은 실제로는 Resource를 생성하고, 그 Resource를 참조하는 적절한 View를 만들어 Pipeline Slot에 바인딩한다는 의미입니다.

```text
CPU Pixel Data
→ GPU Texture2D Resource 생성
→ ShaderResourceView 생성
→ Shader Resource Slot에 SRV 바인딩
→ Shader가 Texture Sample
```

### Resource와 View는 같은 객체가 아님

- Texture는 데이터의 저장 공간입니다.
- RTV·DSV·SRV는 Texture를 Color 출력, Depth 출력, Shader 입력 중 어떤 방식으로 사용할지 나타냅니다.
- View는 원본 데이터를 복제하지 않고 Resource의 특정 Format 또는 Mip·Array 범위를 참조할 수 있습니다.

## Problem / Solved

> 오늘 Commit에서 해결이 완료된 Texture 표시 문제는 확인되지 않았습니다. 현재 구현은 이미지의 CPU Pixel 로드 단계입니다.

## Decision

- 이미지 Decode에는 단일 Header Library인 `stb_image`를 사용합니다.
- 입력 Image Channel 수와 관계없이 `STBI_rgb_alpha`를 요청해 RGBA 형식으로 변환합니다.
- `STB_IMAGE_IMPLEMENTATION`은 `Texture.cpp` 한 곳에만 정의합니다.
- DepthStencilView는 명시적인 Descriptor를 사용합니다.

## Issue

- `stbi_load()`가 반환한 CPU Pixel 메모리에 아직 `stbi_image_free()`를 호출하지 않아 현재 경로에는 메모리 누수가 있습니다.
- 로드한 `imageWidth`, `imageHeight`를 `Texture::width`, `Texture::height`에 저장하지 않습니다.
- `ID3D11Texture2D` 생성, 초기 Pixel 업로드와 `ID3D11ShaderResourceView` 생성은 아직 구현되지 않았습니다.
- Texture/SRV를 Shader에 바인딩하는 코드와 Sampler State가 없습니다.
- Test Level의 지역 변수 `texture`는 초기화 함수 종료 시 소멸하므로 장기 소유 구조가 아직 없습니다.
- `Assets/T_Checker.jpg`는 실행 Working Directory에 따라 상대 경로로 찾지 못할 수 있으며 Build 출력 폴더로 복사하는 설정은 없습니다.
- `Renderer.cpp`에 후행 공백 1건이 확인됐지만 사용자 요청에 따라 소스는 수정하지 않았습니다.
