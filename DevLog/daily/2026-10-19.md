## Implementation

### Camera Constant Buffer 추가

- `Renderer::CameraBufferData`에 View Matrix를 저장하도록 구성했습니다.
- `cameraData`는 CPU에서 관리하는 Camera 데이터이고, `cameraBuffer`는 같은 데이터를 Vertex Shader에 전달하는 D3D11 Constant Buffer입니다.
- Renderer 생성 시 Camera Buffer를 만들고, 해제 시 Device와 DeviceContext보다 먼저 Buffer를 해제합니다.

```cpp
struct CameraBufferData
{
    Matrix4 viewMatrix = Matrix4::Identity;
};
```

### Camera 데이터 제출·갱신·바인딩 흐름

- `TestLevel::Draw()`에서 `Matrix4::LookAt()`으로 View Matrix를 만듭니다.
- `Renderer::SubmitCamera()`가 View Matrix를 CPU의 `cameraData`에 저장합니다.
- `Renderer::UpdateCameraBuffer()`가 `Map()`과 `memcpy()`를 사용해 GPU Constant Buffer를 갱신합니다.
- `VSSetConstantBuffers(1, 1, &cameraBuffer)`로 Vertex Shader의 `b1` Slot에 Camera Buffer를 바인딩합니다.

```text
TestLevel::Draw
→ Matrix4::LookAt
→ Renderer::SubmitCamera
→ cameraData 갱신
→ Renderer::UpdateCameraBuffer
→ cameraBuffer 갱신
→ VSSetConstantBuffers(b1)
→ Vertex Shader View 변환
```

### Vertex Shader에 View 변환 추가

- 기존 `b0` Transform Buffer는 물체별 World Matrix를 전달합니다.
- 새 `b1` Camera Buffer는 현재 View의 View Matrix를 전달합니다.
- Vertex Shader에서 Local 정점을 World Space로 바꾼 뒤 View Space로 변환합니다.

```hlsl
float4 worldPosition = mul(float4(pos, 1), world);
float4 viewPosition = mul(worldPosition, view);
return viewPosition;
```

### Camera Buffer 복사 오류 수정

- 최초 변경에는 `mapped.pData`에 `&cameraBuffer`를 복사하는 오류가 있었습니다.
- `cameraBuffer`는 D3D Buffer 객체를 가리키는 Pointer이므로 View Matrix 데이터가 아닙니다.
- 실제 CPU 데이터인 `&cameraData`를 복사하도록 수정했습니다.
- Camera Buffer 생성·Map 실패 메시지도 Transform Buffer가 아닌 Camera Buffer를 가리키도록 수정했습니다.

### 빌드 검증

- 프로젝트 기본 설정인 `v145` Platform Toolset은 현재 환경에 설치되어 있지 않아 최초 빌드가 중단됐습니다.
- 프로젝트 파일은 변경하지 않고 검증 명령에 설치된 `v143`을 지정했습니다.
- Debug x64 전체 솔루션 빌드 결과: 경고 0개, 오류 0개.

## Learned

### World 데이터와 Camera 데이터의 사용 범위

`RenderCommand`의 World Matrix, Mesh, Shader는 그릴 물체마다 달라질 수 있습니다. 반면 View Matrix는 같은 카메라로 그리는 물체들이 공유합니다.

| 데이터 | 현재 Slot | 변경 주기 | 의미 |
|---|---:|---|---|
| World Matrix | `b0` | 물체별 Draw 전 | Local 정점을 World Space로 이동 |
| View Matrix | `b1` | Camera/View별 | World 정점을 Camera 기준으로 변환 |

따라서 Camera 데이터는 개별 `RenderCommand`에 반복 저장하기보다 별도의 View 단위 데이터로 전달하는 편이 자연스럽습니다.

### Camera 수와 Buffer 수는 반드시 같지 않음

Camera가 여러 개라고 해서 Camera마다 D3D Constant Buffer 객체를 반드시 하나씩 만들어야 하는 것은 아닙니다.

```text
Camera A 데이터로 Buffer 갱신·바인딩
→ Camera A가 보는 장면 Draw

Camera B 데이터로 같은 Buffer 갱신·바인딩
→ Camera B가 보는 장면 Draw
```

하나의 Dynamic Constant Buffer를 Camera별 Render Pass 전에 다시 갱신해 재사용할 수 있습니다. 반대로 여러 Camera를 동시에 참조하거나 병렬 Command 생성, Frame 중 데이터 보존이 필요하면 Camera별 Buffer 또는 Ring Buffer 같은 구성이 필요할 수 있습니다. 즉 Buffer 구성은 Camera 개수 자체보다 Render 순서와 데이터 수명으로 결정합니다.

현재 CraftEngine은 한 Frame에 Camera 하나만 제출하고 장면을 한 번 그리는 구조입니다.

### HLSL `cbuffer`의 선언 순서와 Register

다음처럼 `register`를 명시하면 실제 Binding Slot은 선언 순서가 아니라 명시한 번호로 결정됩니다.

```hlsl
cbuffer Buffer1 : register(b1) { ... } // b1
cbuffer Buffer2 : register(b0) { ... } // b0
```

C++에서도 같은 Slot에 Buffer를 바인딩해야 합니다.

```cpp
context->VSSetConstantBuffers(0, 1, &transformBuffer); // b0
context->VSSetConstantBuffers(1, 1, &cameraBuffer);    // b1
```

`register`를 생략하면 Compiler가 사용 가능한 Slot을 자동 배정할 수 있지만, C++ Binding 코드와의 계약이 불명확해집니다. Engine 코드에서는 명시적인 Register를 사용해 대응 관계를 고정하는 편이 안전합니다.

### `main`과 `SV_POSITION`의 역할

- `main`은 `D3DCompileFromFile()`에 Entry Point로 전달한 함수 이름입니다. 이름 자체가 특별한 것이 아니라 Compile 인자와 HLSL 함수 이름이 일치해야 합니다.
- Vertex Shader 출력의 `SV_POSITION`은 Rasterizer가 정점 위치로 사용할 System-Value Semantic입니다.
- 삼각형을 정상적으로 Rasterize하려면 Vertex Shader가 정점 위치를 `SV_POSITION`으로 전달해야 합니다.

중요한 정정은 Vertex Shader가 반환하는 `SV_POSITION`이 곧바로 NDC가 아니라는 점입니다.

```text
Vertex Shader 출력
= Clip Space 좌표 (x, y, z, w)

GPU의 Perspective Divide
= (x/w, y/w, z/w)

Perspective Divide 결과
= NDC
```

현재 Shader에는 Projection Matrix가 없으므로 View Space 좌표를 `SV_POSITION`에 직접 반환하고 있습니다. 따라서 완전한 3D Camera 변환은 아직 아니며, 좌표가 우연히 Clip 범위 안에 있을 때만 기대한 것처럼 보일 수 있습니다.

### NDC 좌표 범위

Direct3D의 NDC 범위는 다음과 같습니다.

```text
X: -1 ~ 1
Y: -1 ~ 1
Z:  0 ~ 1
```

전통적인 OpenGL NDC에서는 X, Y, Z가 모두 `-1 ~ 1` 범위입니다. API에 따라 Depth 범위가 다르므로 Projection Matrix도 해당 규약에 맞춰 만들어야 합니다.

### 투영이란 무엇인가?

투영은 Camera/View Space의 3차원 점을 화면에 표시할 수 있는 규격화된 공간으로 옮기는 변환입니다.

Perspective Projection에서는 다음 효과를 만듭니다.

- 카메라에서 멀리 있는 물체가 작게 보입니다.
- 카메라 시야각과 화면 Aspect Ratio가 반영됩니다.
- Near Plane과 Far Plane 사이의 깊이가 Direct3D의 Depth 범위로 변환됩니다.
- Clip Space의 `w`에 깊이와 관련된 값을 넣어 이후 `x/w`, `y/w`, `z/w` 나눗셈이 원근감을 만듭니다.

즉 단순히 Z를 버리고 XY만 사용하는 것이 아니라, 3차원 시야 절두체를 GPU가 Clip하고 Rasterize할 수 있는 표준 공간으로 변환하는 과정입니다.

### 추가된 것은 Vertex Buffer가 아니라 Constant Buffer

이번 변경에서 늘어난 Buffer는 정점 위치를 보관하는 Vertex Buffer가 아닙니다.

- Vertex Buffer: Mesh의 정점 위치 같은 Geometry 데이터
- Transform Constant Buffer: 물체별 World Matrix
- Camera Constant Buffer: View 단위 View Matrix

Renderer가 새 Buffer를 생성하고 Vertex Shader에 바인딩해야 화면에 반영된다는 흐름은 맞지만, Buffer의 종류를 구분해야 합니다.

### 상용 Engine에서 Camera와 Renderer의 관계

“Renderer가 Camera에 있다”는 표현은 Engine마다 구조가 달라 일반 규칙으로 보기는 어렵습니다. 보통 Camera는 View·Projection과 Render Target 같은 **한 시점의 렌더링 조건**을 제공하고, 중앙 Renderer 또는 Render Pipeline이 해당 Camera 기준으로 장면을 수집하고 그립니다.

현재 CraftEngine에서도 Camera 객체가 Renderer를 소유하는 구조라기보다 `TestLevel`이 Camera 역할의 데이터를 만들고 중앙 `Renderer`에 제출하는 구조입니다.

## Problem / Solved

### Camera Buffer에 잘못된 주소 복사

**Problem**

`UpdateCameraBuffer()`가 CPU의 View Matrix 데이터가 아니라 `ID3D11Buffer*` 변수의 주소를 복사하고 있었습니다.

**Solved**

```cpp
std::memcpy(mapped.pData, &cameraData, sizeof(CameraBufferData));
```

실제 `CameraBufferData`를 복사하도록 수정했습니다.

### 현재 환경에 v145 Toolset 없음

**Problem**

프로젝트가 지정한 `v145` Platform Toolset을 현재 Visual Studio 설치에서 찾을 수 없었습니다.

**Solved**

저장소 설정을 임의로 변경하지 않고 이번 검증 명령에서 `v143`을 지정해 빌드를 완료했습니다.

## Decision

- 물체별 World Matrix는 Vertex Shader `b0`을 유지합니다.
- Camera View Matrix는 별도의 Constant Buffer로 분리해 `b1`에 바인딩합니다.
- Camera 데이터는 Render Command마다 복제하지 않고 Renderer의 View 단위 데이터로 관리합니다.
- 현재 단계에서는 View Matrix만 추가하고 Projection Matrix는 후속 구현으로 남깁니다.

## Issue

- Projection Matrix가 없어 View Space 좌표가 그대로 `SV_POSITION`에 전달됩니다.
- Camera가 별도 객체가 아니라 `TestLevel::Draw()`의 지역 데이터로 구성됩니다.
- 한 Frame에 여러 Camera로 장면을 반복 Render하는 구조는 아직 없습니다.
- Camera Buffer를 매 Frame 갱신하며 변경 여부를 검사하지 않습니다.
- 프로젝트의 `v145` Toolset과 현재 설치된 `v143` 사이에 환경 차이가 있습니다.
