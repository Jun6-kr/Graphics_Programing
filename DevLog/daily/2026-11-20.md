## Implementation

### Asset Importer 실행 프로젝트 추가

- Game Runtime과 분리된 Console Application인 `CraftAssetImporter` 프로젝트를 Solution에 추가했습니다.
- Importer는 Source Directory와 Output Directory를 Command Line Argument로 전달받습니다.
- Source Directory가 존재하는지 검사한 뒤 `std::filesystem::recursive_directory_iterator`로 하위 파일을 순회합니다.

```text
CraftAssetImporter <source_dir> <output_dir>
```

### Source와 Imported Asset 경로 분리

- 원본 파일을 보관할 `Assets/Source`와 변환 결과를 저장할 `Assets/Imported` 경로를 구분했습니다.
- Test Level이 사용하는 Checker Texture 경로를 `Assets/Source/Textures/T_Checker.png`로 변경했습니다.

```text
Assets/Source
→ CraftAssetImporter
→ Assets/Imported
```

### Assimp 의존성 준비

- Importer 프로젝트의 Include 경로에 저장소의 `Includes` Directory를 추가했습니다.
- Assimp Header를 `Includes/Assimp`에 추가했습니다.
- Debug 구성에서 Assimp Library를 Link하고 Pre-Build Event에서 Assimp DLL을 출력 Directory로 복사하도록 설정했습니다.
- 이미지 처리를 위한 `stb_image.h`도 공용 Include Directory에 추가했습니다.

### Import 실행 Batch File 추가

- `Tools/AssetImporter.bat`에서 저장소 Root를 기준으로 Source·Output·Importer 실행 파일 경로를 계산합니다.
- 실행 인자가 있으면 기본 Source·Output 경로를 덮어쓸 수 있습니다.
- Importer 실행 파일이 없으면 실패 Code를 반환하고, 실행 후에는 Importer의 `%errorlevel%`을 그대로 전달합니다.

## Learned

### Runtime과 Asset Build Tool의 분리

- 모델·이미지 원본을 Game Runtime에서 매번 직접 해석하는 대신 별도 Tool에서 Engine 전용 형식으로 변환할 수 있습니다.
- Runtime은 변환된 Asset만 읽도록 구성하면 원본 Format마다 필요한 Parsing 비용과 외부 Library 의존성을 Tool 쪽으로 분리할 수 있습니다.

### Command Line Tool의 기본 구조

- `argc`, `argv`로 외부에서 경로를 전달받을 수 있습니다.
- `std::filesystem`을 사용하면 Directory 존재 확인, 재귀 순회와 경로 결합을 Platform 문자열 처리보다 일관되게 수행할 수 있습니다.
- Process의 반환 Code는 Batch나 다른 Build Tool이 성공·실패를 판단하는 값으로 사용할 수 있습니다.

### Batch File의 저장소 상대 경로

- `%~dp0`은 실행 중인 Batch File이 위치한 Directory를 나타냅니다.
- Batch 위치를 기준으로 Root를 계산하면 사용자의 현재 Working Directory와 무관하게 Tool과 Asset 경로를 찾을 수 있습니다.
- `setlocal`은 Batch 내부 Environment Variable 변경이 외부 Shell에 남지 않도록 제한합니다.

## Problem / Solved

### 원본 Asset과 Runtime Asset의 구분이 없음

**Problem**

- 기존에는 Game이 원본 Texture 파일을 직접 읽었으며 Asset 변환 Tool과 출력 경로가 없었습니다.

**Solved**

- Source·Imported Directory를 구분하고 별도 Importer 프로젝트와 실행 Batch의 초기 구조를 추가했습니다.

## Decision

- Asset 변환은 Engine이나 Game이 아닌 별도 Console Application에서 수행합니다.
- 기본 Source는 `Assets/Source`, 기본 Output은 `Assets/Imported`를 사용합니다.
- Third-party Header는 저장소 Root의 `Includes`에서 관리합니다.

## Issue

- 현재 Importer는 파일을 순회해 경로만 출력하며 실제 Asset 변환은 수행하지 않습니다.
- Batch File은 Debug Importer 실행 파일을 기본값으로 사용합니다.
- Release 구성의 Assimp Link Library 설정은 Debug 구성과 동일하게 준비되어 있는지 확인이 필요합니다.
- Game은 아직 Imported Asset이 아니라 Source Texture를 직접 사용합니다.
- 사용자 요청에 따라 빌드·실행·테스트는 수행하지 않았습니다.
