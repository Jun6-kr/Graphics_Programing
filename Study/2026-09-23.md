# 2026-09-23 - Message Loop & Direct3D11 기본 구조

## 1. Engine::Run()의 메시지 루프

Windows 프로그램은 `Engine::Run()` 안에서 반복적으로 메시지를 확인하고,
처리할 메시지가 없을 때 게임의 렌더링 작업을 진행한다.

기본 흐름:

```text
while (프로그램 실행 중)
    ↓
PeekMessage()
    ↓
메시지가 있으면
    TranslateMessage()
    DispatchMessage()
        ↓
    Win32MessageHandler()
        ↓
    Engine::HandleMessage()

메시지가 없으면
    Draw()
```

### PeekMessage

메시지 큐에 처리할 Windows Message가 있는지 확인하고 가져온다.

```text
Windows Event
    ↓
Message Queue
    ↓
PeekMessage()
    ↓
MSG 구조체
```

`PeekMessage()` 자체가 메시지를 처리하는 것은 아니다.

### TranslateMessage

주로 키보드 메시지를 문자 입력 메시지로 변환하는 데 사용된다.

예:

```text
WM_KEYDOWN
    ↓
TranslateMessage()
    ↓
필요한 경우 WM_CHAR 생성
```

### DispatchMessage

가져온 메시지를 해당 Window의 WndProc으로 전달한다.

현재 프로젝트에서는 `WNDCLASS::lpfnWndProc`에 등록된
`Win32Window::Win32MessageHandler`가 호출된다.

```text
DispatchMessage()
    ↓
Win32MessageHandler()
    ↓
Win32Window*
    ↓
IMessageHandler*
    ↓
Engine::HandleMessage()
```

CreateDevices()

## 3. Device와 DeviceContext

Direct3D 11에서 가장 먼저 생성하는 핵심 객체는 다음 두 개다.

```cpp
ID3D11Device* device;
ID3D11DeviceContext* context;
```

둘의 역할은 명확히 다르다.

### Device

`ID3D11Device`는 GPU에서 사용할 리소스를 **생성하는 역할**을 한다.

현재 코드의 예:

```cpp
device->CreateBuffer(...);
device->CreateRenderTargetView(...);
device->CreateVertexShader(...);
device->CreatePixelShader(...);
device->CreateInputLayout(...);
```

정리:

```text
Device
= 리소스를 만든다
```

단, `ID3D11Device` 자체가 물리적인 그래픽카드라는 의미는 아니다.

```text
물리 GPU
    ↑
그래픽 드라이버
    ↑
Direct3D 11
    ↑
ID3D11Device
```

즉 Direct3D를 통해 GPU 리소스를 생성하고 관리하기 위한 논리적인 인터페이스다.

### DeviceContext

`ID3D11DeviceContext`는 이미 생성된 리소스를
그래픽 파이프라인에 연결하고 GPU에 명령을 전달한다.

현재 코드의 예:

```cpp
context->OMSetRenderTargets(...);
context->IASetVertexBuffers(...);
context->IASetIndexBuffer(...);
context->VSSetShader(...);
context->PSSetShader(...);
context->RSSetViewports(...);
context->DrawIndexed(...);
```

정리:

```text
Device
= 만든다

DeviceContext
= 설정하고 명령한다
```

## 4. SwapChain의 역할

`SwapChain`은 GPU에게 직접 그리기 명령을 내리는 객체가 아니다.

그리기 명령은 `DeviceContext`가 담당한다.

`SwapChain`의 역할은:

> 최종 화면을 저장하는 버퍼들을 관리하고,
> 완성된 화면을 특정 HWND Window에 표시하는 것

이다.

현재 코드에서:

```cpp
swapChainDesc.BufferCount = 2;
swapChainDesc.OutputWindow = window.GetHandle();
swapChainDesc.Windowed = true;
```

즉 SwapChain은:

```text
SwapChain
    ├─ 화면 Buffer 관리
    └─ 출력할 HWND 기억
```

한다.

완성된 화면은 마지막에:

```cpp
swapChain->Present(vsync, 0);
```

를 통해 Window에 표시된다.

## 5. Back Buffer란?

Back Buffer는 **이번 프레임의 최종 화면 이미지가 저장되는 실제 메모리 공간**이다.

Direct3D에서는 이것이 `ID3D11Texture2D` 리소스 형태로 존재한다.

```text
Back Buffer
= 최종 화면용 2D Texture
= 실제 픽셀 데이터가 저장되는 공간
```

SwapChain에서 다음과 같이 가져온다.

```cpp
ID3D11Texture2D* backBuffer = nullptr;

swapChain->GetBuffer(
    0,
    IID_PPV_ARGS(&backBuffer)
);
```

중요한 점:

> SwapChain이 그림을 그리는 것이 아니라,
> GPU가 렌더링한 결과가 Back Buffer에 저장된다.

---

## 6. RenderTargetView(RTV)의 역할

여기서 가장 헷갈렸던 부분.

`RenderTargetView`는 HWND와 Back Buffer를 연결하는 객체가 아니다.

RTV의 역할은:

> 특정 Texture Resource를 "렌더링 결과를 기록할 대상"으로 지정하는 것

이다.

현재 코드는 SwapChain의 Back Buffer를 기반으로 RTV를 만든다.

```cpp
device->CreateRenderTargetView(
    backBuffer,
    nullptr,
    &renderTargetView
);
```

관계는:

```text
RenderTargetView
    ↓
Back Buffer
```

즉 RTV는:

> "GPU의 최종 렌더링 결과를 이 Back Buffer에 써라"

라는 목적지 역할을 한다.

---

## 7. OMSetRenderTargets

실제 렌더링 전에 다음 코드가 실행된다.

```cpp
context->OMSetRenderTargets(
    1,
    &renderTargetView,
    nullptr
);
```

이 코드는 그림을 직접 그리는 것이 아니다.

의미는:

> 앞으로 그래픽 파이프라인의 최종 출력 결과를
> 이 RTV가 가리키는 Resource에 기록하라.

이다.

현재 RTV는 Back Buffer를 가리키므로:

```text
GPU Rendering Result
    ↓
RenderTargetView
    ↓
Back Buffer
```

가 된다.

---

## 8. 실제로 Back Buffer에 그림을 쓰는 주체

실질적으로 Back Buffer에 픽셀 데이터를 기록하는 주체는 **GPU**다.

역할을 구분하면 다음과 같다.

```text
DeviceContext
= GPU에게 명령 전달

GPU
= 실제 렌더링 계산 수행

RenderTargetView
= 렌더링 결과를 저장할 위치 지정

Back Buffer
= 실제 픽셀 데이터 저장

SwapChain
= Back Buffer 관리 및 Window에 표시
```

현재 코드에서는:

```cpp
context->DrawIndexed(3, 0, 0);
```

가 Draw Call을 발생시키고,
GPU가 그래픽 파이프라인을 수행한다.

개념적인 흐름:

```text
Vertex Buffer
    ↓
Vertex Shader
    ↓
Rasterizer
    ↓
Pixel Shader
    ↓
Output Merger
    ↓
RTV가 가리키는 Back Buffer에 픽셀 기록
```

---

## 9. ClearRenderTargetView

다음 코드 역시 Back Buffer의 픽셀 데이터를 변경한다.

```cpp
context->ClearRenderTargetView(
    renderTargetView,
    backgroundColor
);
```

의미:

> RTV가 가리키는 Back Buffer 전체를 지정한 색으로 채운다.

한 프레임의 기본 흐름은 다음과 같다.

```text
1. OMSetRenderTargets()
   → 어디에 그릴지 지정

2. ClearRenderTargetView()
   → Back Buffer를 배경색으로 초기화

3. DrawIndexed()
   → GPU가 실제 도형을 계산하고 Back Buffer에 기록

4. Present()
   → 완성된 Back Buffer를 HWND Window에 표시
```

## 10. 가장 중요한 관계 정리

오늘 학습에서 가장 중요하게 구분한 구조:

```text
DeviceContext
    ↓
GPU에 Draw 명령

GPU
    ↓
실제 렌더링 수행

RenderTargetView
    ↓
저장할 Resource 지정

Back Buffer
    ↓
최종 픽셀 데이터 저장

SwapChain
    ↓
Present()

HWND Window
    ↓
화면에 표시
```

특히 혼동하지 말아야 할 두 연결:

```text
GPU 출력 대상 지정
RenderTargetView
    ↓
Back Buffer
```

```text
최종 화면 표시 대상 지정
SwapChain
    ↓
HWND
```

따라서:

> RTV의 "출력 위치 지정"은 HWND를 지정한다는 뜻이 아니라,
> 렌더링 결과를 저장할 Back Buffer(또는 다른 Texture Resource)를 지정한다는 뜻이다.
