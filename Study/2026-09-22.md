# 2026-09-22 - Win32 Window 학습 정리

## 1. 프로그램 시작 흐름

현재 프로그램의 시작 흐름은 다음과 같다.

```text
main / WinMain
    ↓
LaunchApplication()
    ↓
Engine 생성
    ↓
Engine::Run()
```

`main` / `WinMain`은 프로그램 진입점이고, 실제 애플리케이션 실행은 `LaunchApplication()`을 통해 `Engine`으로 넘긴다.

---

## 2. Engine이 소유하는 객체

`Engine`은 직접 만든 두 객체를 `std::unique_ptr`로 소유한다.

```cpp
std::unique_ptr<Win32Window> window;
std::unique_ptr<Renderer> renderer;
```

생성자에서는 다음 순서로 생성한다.

```cpp
window = std::make_unique<Win32Window>(width, height, this, title);
renderer = std::make_unique<Renderer>(*window);
```

- `Win32Window`: Windows 창을 만들고 관리하는 래퍼 클래스
- `Renderer`: 렌더링을 담당하는 클래스
- `unique_ptr`: `Engine`이 두 객체의 수명을 단독으로 소유한다는 의미

`Renderer`가 Window 정보를 필요로 하기 때문에 Window가 먼저 생성된다.

---

## 3. Win32Window와 실제 Windows 창

`Win32Window` 객체 자체가 화면에 보이는 창은 아니다.

```text
Win32Window
= C++에서 Windows 창을 관리하기 위해 만든 객체

HWND
= Windows OS가 실제 창 하나를 식별하는 핸들
```

즉 메모장이나 계산기처럼 화면에 보이는 실제 창은 Windows가 관리하며,
우리 코드에서는 그 창을 `HWND`를 통해 참조한다.

---

## 4. HINSTANCE와 HWND

### HINSTANCE

`HINSTANCE`는 현재 실행 중인 프로그램 모듈을 Windows가 식별하기 위한 핸들이다.

```cpp
instance(GetModuleHandle(nullptr))
```

쉽게 말하면:

```text
HINSTANCE = 어느 프로그램인가?
```

### HWND

`HWND`는 실제 창 하나를 식별한다.

```text
HWND = 어느 창인가?
```

하나의 프로그램이 여러 창을 만들 수도 있으므로 둘은 다른 개념이다.

```text
프로그램 (HINSTANCE)
    ├─ 창 A (HWND)
    ├─ 창 B (HWND)
    └─ 창 C (HWND)
```

---

## 5. WNDCLASS의 역할

`WNDCLASS`는 실제 창이 아니라 Windows에 등록할 **창의 규칙/설계 정보**를 담는 구조체이다.

```cpp
WNDCLASS wc = {};

wc.lpfnWndProc = Win32MessageHandler;
wc.hInstance = instance;
wc.lpszClassName = className.c_str();
wc.style = CS_HREDRAW | CS_VREDRAW;
```

주요 항목:

- `lpfnWndProc`: 이 종류의 창에서 메시지가 발생했을 때 Windows가 호출할 함수
- `hInstance`: 이 창 클래스를 등록하는 프로그램
- `lpszClassName`: 창 클래스의 이름
- `style`: 창 클래스의 동작 방식

작성한 정보는 다음과 같이 Windows에 등록한다.

```cpp
RegisterClass(&wc);
```

```text
WNDCLASS 작성
    ↓
RegisterClass()
    ↓
Windows에 "이런 규칙의 창을 사용하겠다"고 등록
```

---

## 6. RegisterClass와 CreateWindow

`RegisterClass()`는 실제 창을 만드는 함수가 아니다.

`WNDCLASS`로 정의한 창 종류를 Windows에 등록한 뒤,
`CreateWindow()`가 그 등록 정보를 이용해 실제 창을 만든다.

```text
WNDCLASS
= 창 설계 정보

RegisterClass
= 설계 정보를 Windows에 등록

CreateWindow
= 등록된 창 클래스를 이용해 실제 창 생성
```

`CreateWindow()`가 반환한 `HWND`는 `Win32Window::handle`에 저장한다.

---

## 7. Windows 메시지와 WndProc

Windows 창에서는 다음과 같은 이벤트가 계속 발생한다.

- 창 생성
- 키 입력
- 창 닫기
- 창 파괴
- 다시 그리기

Windows는 이를 Message로 전달한다.

예:

```text
WM_CREATE
WM_KEYDOWN
WM_CLOSE
WM_DESTROY
WM_PAINT
```

Windows가 메시지를 전달하기 위해 요구하는 함수 형식은 다음과 같다.

```cpp
LRESULT CALLBACK 함수이름(
    HWND hwnd,
    UINT message,
    WPARAM wParam,
    LPARAM lParam
);
```

함수 이름 자체는 중요하지 않다.

중요한 것은 **반환형, 호출 규약, 파라미터 타입이 `WNDPROC` 규격과 맞는가**이다.

현재 프로젝트에서는 다음 함수를 등록한다.

```cpp
static LRESULT CALLBACK Win32MessageHandler(
    HWND window,
    UINT message,
    WPARAM wparam,
    LPARAM lparam
);
```

이 함수 포인터를 `WNDCLASS::lpfnWndProc`에 저장해 두면,
Windows가 해당 창의 메시지가 발생할 때 이 함수를 호출한다.

---

## 8. 왜 Win32MessageHandler는 static인가?

일반 C++ 멤버 함수에는 암묵적인 `this`가 존재한다.

개념적으로는:

```text
일반 멤버 함수

Win32Window* this
HWND
UINT
WPARAM
LPARAM
```

와 비슷하다.

하지만 Windows가 요구하는 WndProc 형식은:

```text
HWND
UINT
WPARAM
LPARAM
```

이다.

따라서 일반 멤버 함수는 Windows가 요구하는 함수 포인터 타입과 맞지 않는다.

`static` 멤버 함수에는 암묵적인 `this`가 없으므로 Windows가 요구하는 콜백 함수 형식으로 사용할 수 있다.

다만 이렇게 하면 새로운 문제가 생긴다.

> static 함수에서는 자신이 어느 `Win32Window` 객체에 속한 메시지를 처리하고 있는지 알 수 없다.

---

## 9. CreateWindow(..., this)의 의미

위 문제를 해결하기 위해 실제 창을 만들 때 마지막 추가 파라미터로 현재 `Win32Window` 객체의 주소를 전달한다.

```cpp
CreateWindow(
    ...,
    this
);
```

여기서 `this`는 `Win32Window*`이다.

중요한 점:

> Windows가 이 값을 `Win32Window*`라고 이해하는 것은 아니다.

Windows 입장에서는 단순히 사용자가 함께 전달한 추가 데이터이다.

---

## 10. WM_CREATE에서 Win32Window* 다시 얻기

창 생성 과정에서 Windows가 `WM_CREATE` 메시지를 보낸다.

이때 `CreateWindow(..., this)`로 넘겼던 추가 데이터가
`CREATESTRUCT::lpCreateParams`를 통해 다시 전달된다.

```cpp
CREATESTRUCT* createStruct =
    reinterpret_cast<CREATESTRUCT*>(lparam);

Win32Window* win32Window =
    reinterpret_cast<Win32Window*>(
        createStruct->lpCreateParams
    );
```

흐름은 다음과 같다.

```text
CreateWindow(..., this)
        ↓
Windows가 추가 데이터로 전달받음
        ↓
WM_CREATE 발생
        ↓
lParam
        ↓
CREATESTRUCT
        ↓
lpCreateParams
        ↓
원래 넘겼던 Win32Window*
```

---

## 11. GWLP_USERDATA로 HWND와 Win32Window 연결

`WM_CREATE`에서 다시 얻은 `Win32Window*`를 해당 `HWND`에 연결해 둔다.

```cpp
SetWindowLongPtr(
    window,
    GWLP_USERDATA,
    reinterpret_cast<LONG_PTR>(win32Window)
);
```

개념적으로는 다음과 같다.

```text
HWND
    ↓
GWLP_USERDATA
    ↓
Win32Window*
```

즉:

> 이 HWND와 연결된 C++ 객체는 이 Win32Window 객체다.

라는 관계를 만들어 두는 것이다.

---

## 12. 이후 메시지에서는 HWND로 객체를 찾는다

`WM_CREATE` 이후 `WM_KEYDOWN`, `WM_CLOSE` 등의 메시지가 들어올 때도
Windows는 `HWND`를 함께 전달한다.

따라서 다음과 같이 이전에 저장한 객체 포인터를 다시 가져올 수 있다.

```cpp
Win32Window* win32Window =
    reinterpret_cast<Win32Window*>(
        GetWindowLongPtr(window, GWLP_USERDATA)
    );
```

흐름:

```text
Windows
    ↓
HWND + Message
    ↓
static Win32MessageHandler()
    ↓
GetWindowLongPtr(HWND, GWLP_USERDATA)
    ↓
Win32Window*
```

이렇게 해서 `static` 함수에서도 실제 C++ 객체에 접근할 수 있다.

---

## 13. Win32Window에서 Engine으로 메시지 전달

`Win32Window`는 다음 포인터를 가지고 있다.

```cpp
IMessageHandler* messageHandler = nullptr;
```

그리고 `Engine`은 `IMessageHandler`를 상속한다.

```cpp
class Engine : public IMessageHandler
```

`Engine`이 `Win32Window`를 만들 때 자신의 `this`를 넘긴다.

```cpp
window = std::make_unique<Win32Window>(
    width,
    height,
    this,
    title
);
```

따라서 `Win32Window::messageHandler`가 실제로 가리키는 객체는 `Engine`이다.

이후 `Win32MessageHandler`는 메시지 처리를 다음 대상으로 위임한다.

```text
Windows
    │
    │ HWND / UINT / WPARAM / LPARAM
    ▼
Win32Window::Win32MessageHandler (static)
    │
    │ HWND의 GWLP_USERDATA 조회
    ▼
Win32Window*
    │
    │ messageHandler
    ▼
IMessageHandler*
    │
    │ 실제 객체는 Engine
    ▼
Engine::HandleMessage()
```

---

## 14. 최종 핵심 정리

현재 구조에는 두 번의 연결이 있다.

```text
1. HWND
      ↓
   Win32Window*

2. Win32Window*
      ↓
   IMessageHandler*
      ↓
   Engine*
```

한 문장으로 정리하면:

> Windows는 `HWND`는 알지만 C++의 `Win32Window` 객체는 모른다. 따라서 Windows가 호출할 수 있는 static 메시지 함수를 등록하고, `CreateWindow(..., this)` → `WM_CREATE` → `GWLP_USERDATA`를 이용해 `HWND`와 `Win32Window` 객체를 연결한다. 이후 `Win32Window`가 가진 `IMessageHandler*`를 통해 실제 메시지 처리를 `Engine::HandleMessage()`로 위임한다.
